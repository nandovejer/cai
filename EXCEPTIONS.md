# LUZ — exceptions register

Strong rules (`SR-n` in [PRINCIPLES.md](./PRINCIPLES.md)) can be broken with a written reason. Red lines (`RL-n`) cannot, and `pnpm check:exceptions` fails if a row tries.

How to add one:

1. Take the next free `EX-nnn` id and add a row below.
2. If the exception lives in a file, put a comment `luz-exception: EX-nnn` next to the code (beside any `stylelint-disable` or `eslint-disable` it needs) and name that file in the *Where* column. If it has no single place in the code, write `—`.
3. Say what is excepted, why, and what would let us remove it.

Exceptions do not expire. Every major release reviews this list and removes what is no longer needed. Delete the row and the comment together when an exception is fixed.

| EX-005 | SR-7 | packages/site/src/search.js | The search component does not use `@luz-ds/core/i18n`. Its fixed text (trigger, dialog title, field label, hint, close button, group names, empty state, no-results hint, A–Z link) is written in the markup, which PRINCIPLES §5 already lets win. The few strings the script writes — the result count, "{shown} of {n} results", "No results for “{query}”.", "Loading the search index…" and the error line — are read from `data-luz-label-*` attributes on the dialog; a missing attribute writes nothing (no English fallback in the module: it did not fit the site JS ceiling). Why: importing core's i18n needs an import map on pages without a build step, and bundling it does not fit the site JS ceiling (2 kB, red line 17). A Spanish page sets the `data-luz-label-*` attributes in Spanish. Remove when site can reach `t()` without an import map and within its budget. | 2026-10-09 |
| EX-006 | SR-8 | packages/core/src/print/_print.css | PRINCIPLES §7 asks for no content-bearing pseudo-elements. In print, `a[href^="http"]::after` writes the address of an external link after its text, so a reader of the paper can follow it. The text of the link is untouched, the rule runs in `@media print` only, and on a screen nothing is added. Remove when browsers print link addresses themselves, or when a print stylesheet is no longer shipped. | 2026-10-11 |
| EX-007 | SR-6 | — | No component has been tested by hand with a screen reader. SR-6 asks for NVDA + Firefox, VoiceOver + Safari, TalkBack + Chrome and Orca + Firefox before a release that changes UI; none has been used on any release, and the accessibility statement says so. Automated checks (axe, keyboard and focus specs, contrast, forced colors, reduced motion) are run on every change, and they do not replace it. The open list of `appearance: base-select`, the search, the language switcher and the site header menu are the parts the statement names. Remove, component by component, when one `tests/manual/SR-6-evidence-template.md` is filled for it. | 2026-10-11 |
| EX-008 | SR-8 | — | On the documentation site, the example video's caption files load only with JavaScript (WCAG 2.2 SC 1.2.2, Captions, Prerecorded). Without it the browser lists the tracks and shows no text. Remove when the build rewrites it, so the markup carries a real `src`. | 2026-10-11 |
| EX-009 | SR-8 | apps/landing/theme-boot.js | PRINCIPLES §3 asks for no JS on the critical rendering path. The home and documentation pages load a classic, render-blocking script in `<head>` (a file of the site, so the CSP keeps `script-src 'self'`) that sets `data-theme` from the stored choice or the OS before the first paint. Without it, every navigation drew the page light and then switched it to dark when the deferred `apps/docs/site-header.js` ran. It is the site's, not a package's: LUZ ships no such script. Remove when a stored color mode can be applied before the first paint without JavaScript, or when `light-dark()` lets the site follow the OS with no stored choice. | 2026-10-12 |
| EX-010 | SR-7 | packages/core/src/timeline.js | The timeline chunk carries its own dictionary of four strings (Previous, Next, Pause, Play; English and Spanish) and a lookup of a few lines (`data-luz-label-<key>` on the element or an ancestor, then the nearest `lang`, then English), instead of importing `@luz-ds/core/i18n`. Why: imported from the entry's i18n, the built chunk imported `luz.js`, so `import "@luz-ds/core/timeline"` booted the whole entry; bundling a second copy of i18n would not reach the strings a consumer adds with `registerLocale()` either. With `luz.js` on the page the entry passes its `t` to `initTimeline()`, so `registerLocale()` and the page language work as for every other component; only a key that dictionary lacks falls back to the chunk's own. Remove when a chunk may read core's dictionary without importing it (SEC-CHUNK-2 forbids a chunk that imports anything, so a shared module is not the way). | 2026-10-14 |
| EX-011 | SR-8 | packages/core/src/highlight.js | The only HTML sink in `packages/core/src`: `highlightBlock()` sets `code.innerHTML` to the tokenized text of a `pre.luz-code-block`. The ESLint rule "No HTML from strings" (security.md SEC-IDX-1) is an error in every package and app; this line carries its one `eslint-disable`. Why: the highlight is `<span class="tok-…">` around escaped text, and building one node per token would cost bytes the entry does not have. What makes it safe: `tokenize()` passes every slice of the source through `escapeHtml()`, its only markup is a `span` with a constant class from `LANGS`, and the input is the block's own `textContent`, never a translation or a string from outside (no dictionary, label or language file reaches it). Remove when the highlight builds nodes with `textContent`, or when the entry has the bytes for it. | 2026-10-15 |
