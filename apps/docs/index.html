Core + Tokens technical documentation

Technical reference for architecture, package boundaries, build flow, and copy/paste integration snippets for @cai-ds/tokens and @cai-ds/core.

!
Beta
CAI is in beta. The tokens, components and patterns work and are tested, but names, classes and behavior can still change before the stable release. Pin an exact version and read the changelog before you upgrade.

Installation

Three layers, adopted in order. Stop at the level you need: each layer requires the ones below it and nothing above it.

Level 1 — Tokens only

CSS custom properties (primitives + light, dark and high-contrast semantics) and one MIT-licensed font, ET Book, for headings. Text and code use the system fonts. No other CAI package needed.

$ pnpm add @cai-ds/tokens 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/tokens@3.0.0/dist/cai-tokens.min.css">

Bringing your own fonts? Load dist/tokens.min.css instead: the same tokens without any @font-face.

Level 2 — Tokens + Core

Components and optional JS behaviors. Core requires tokens, loaded first.

$ pnpm add @cai-ds/tokens @cai-ds/core 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/tokens@3.0.0/dist/cai-tokens.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/core@3.0.0/dist/cai.min.css">

<!-- Optional JS behaviors -->
<script type="module" src="https://cdn.jsdelivr.net/npm/@cai-ds/core@3.0.0/dist/cai.min.js"></script>

Level 3 — Tokens + Core + Platform

App-shell patterns. Platform requires both core and tokens.

$ pnpm add @cai-ds/tokens @cai-ds/core @cai-ds/platform 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/tokens@3.0.0/dist/cai-tokens.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/core@3.0.0/dist/cai.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/platform@3.0.0/dist/platform.min.css">

<!-- Optional JS behaviors -->
<script type="module" src="https://cdn.jsdelivr.net/npm/@cai-ds/core@3.0.0/dist/cai.min.js"></script>

Notes

  • npm and pnpm install the required lower layers automatically; Yarn only warns, so list every package as above.
  • Pin exact versions on a CDN and add an integrity hash in production.
  • A console warning tells you when a layer is loaded without the one below it.

Package boundaries

Unidirectional dependency chain.
@cai-ds/tokens   -> primitives + semantic token contracts (standalone)
      ↓ required by
@cai-ds/core     -> reusable CSS components + optional JS behaviors
      ↓ required by
@cai-ds/platform -> app-shell patterns (documented at /platform/)

Tokens (Technical)

Two-layer token model. Components consume semantic tokens only.

Layer model

packages/tokens/tokens.json
  -> source of primitives (blue-10..100, gray-10..100, spacing, radius...)

packages/tokens/dist/cai-tokens.css
  Layer 1: generated primitives
  Layer 2: handwritten semantics per theme (light/dark/high-contrast)

Component token rule

/* Correct: semantic tokens */
color: var(--cai-text-primary);
background: var(--cai-brand-primary);
border-color: var(--cai-border-subtle);

/* Incorrect: primitive scales */
color: var(--cai-gray-100);
background: var(--cai-blue-60);

Type scale and minimum sizes

Every size is in rem, so text follows the font size the reader sets in the browser, not only page zoom (WCAG 1.4.4). The scale is the same at every viewport width: no breakpoint makes text smaller.

Font-size tokens
TokenValueAt 16px rootUse
--cai-text-xs0.75rem12pxAbsolute floor. Micro-copy only: badges, tags, counters, version labels. Never running text.
--cai-text-sm0.875rem14pxFloor for secondary and UI text: helper and error text, captions, table headers, breadcrumbs, tooltips.
--cai-text-md0.9375rem15pxDefault UI text: buttons, labels, table cells, tabs, navigation.
--cai-text-base1rem16pxBody and running text. Form fields on touch screens.
--cai-text-lg1.25rem20pxLead paragraphs, dialog titles.
--cai-text-xl1.5rem24pxHeadings.
--cai-text-2xl2rem32pxHeadings.
--cai-text-3xl2.625rem42pxPage titles.
--cai-text-4xl3.375rem54pxDisplay.
  • Body text is never below --cai-text-base (16px), with a line height of 1.5.
  • Secondary and UI text is never below --cai-text-sm (14px).
  • Nothing goes below --cai-text-xs (12px). Sizes relative to their context (kbd, time, output, inline code, captions) are clamped with max() so they cannot fall below the floor inside small text.
  • Form fields use --cai-text-control (core setting): --cai-text-md on desktop, --cai-text-base (16px) at 768px and below and on touch screens, where iOS Safari zooms the page into any smaller field.

Solid fills

Surfaces that carry --cai-text-on-color use the fill tokens, not the brand or status color directly: --cai-brand-fill, --cai-brand-fill-hover, --cai-brand-fill-active and --cai-color-danger-fill. In light and high contrast they equal the brand and danger colors; in dark mode they are a step darker, because the dark brand is light enough to be read as text and white on it falls below 4.5:1.

Add primitive token

  1. Edit packages/tokens/tokens.json.
  2. Run pnpm tokens:build.
  3. Map to semantics only if needed.

Add semantic token

  1. Edit packages/tokens/src/semantic.css in all 3 theme blocks, then run pnpm tokens:build.
  2. Keep names stable across light, dark, and high-contrast.
  3. Use the semantic token in components.

Core (Technical)

Core ships ITCSS layers + optional vanilla JS behavior helpers.

CSS architecture (ITCSS)

packages/core/src/
  settings/_settings.css
  generic/_reset.css
  elements/_elements.css
  objects/_objects.css
  components/_components.css
  utilities/_utilities.css

JS behavior entrypoint

import "/packages/core/dist/cai.js";

// Includes helpers for:
// - theme persistence
// - copy buttons
// - tabs and media player bindings
// - syntax-highlight utility for code blocks

Minimal page skeleton

<html lang="en" data-theme="minimalist">
<head>
  <link rel="stylesheet" href="/packages/tokens/dist/cai-tokens.css">
  <link rel="stylesheet" href="/packages/core/dist/cai.css">
</head>
<body>
  <button class="cai-btn cai-btn--primary">Run action</button>
  <div class="cai-field">
    <label class="cai-field__label" for="email">Email</label>
    <input id="email" class="cai-input" type="email">
  </div>
</body>
</html>

Themes & modes

Identity and color mode are independent.
<html data-theme="minimalist" data-mode="light">

<html data-theme="minimalist" data-mode="dark">

<!-- Custom identity -->
<html data-theme="ricardoymortimer" data-mode="high-contrast">

Accessibility statement

What CAI aims for, what is checked on every change, and what has not been tested. Last reviewed on 6 October 2026.

Target

CAI aims to meet WCAG 2.2 level AA, the level that EN 301 549 and the European Accessibility Act refer to. A design system cannot make a service accessible by itself: how you use the components decides the result.

What is checked on every change

  • An automated scan with axe-core of the four apps, in the light, dark and high-contrast modes. A serious or critical finding fails the build.
  • Keyboard use of the sidebar drawer, the modal dialog and the tabs.
  • The pages with JavaScript turned off: content is readable at 320 pixels wide, and no control that needs JavaScript is left on screen doing nothing.
  • Reduced motion: no transition or animation runs when the visitor asks for less motion.
  • Forced colors: a focused button keeps a visible outline.
  • Contrast of the text written for the landing page, in all three modes.

What has not been tested

  • Screen readers. NVDA, JAWS, VoiceOver and TalkBack have not been used to test CAI. Nothing here says a component works with them.
  • Speech recognition and screen magnifier software.
  • Zoom to 400 percent by hand. Only the 320 pixel width is measured.
  • Research with disabled people.

Automated tools find only part of the problems. Treat this list as the gap, and test your own pages.

Known issues

  • The tooltip cannot be dismissed with the Escape key. This partly fails WCAG 1.4.13 (Content on hover or focus). Keep tooltips non-essential.
  • The items of the icon grid are made focusable and given the button role by a script, on a div. A native button is planned.
  • The modal buttons use the command and commandfor attributes. In a browser without them, and without JavaScript, the open button does nothing.
  • The MIDI player needs JavaScript and Web Audio. Without them it shows a message.
  • A stored color mode can flash once on load, because no inline script sets it before the first paint.

Report a problem

If something does not work for you, open an issue on GitHub and say what you were trying to do, the browser and the assistive technology you use.
