Installation

Three layers, adopted in order. Stop at the level you need: each layer requires the ones below it and nothing above it.

Level 1: tokens only

CSS custom properties (primitives + light, dark and high-contrast semantics) and one MIT-licensed font, ET Book, for headings. The vejer identity also sets running text in it. Text and code use the system fonts. No other CAI package needed.

$ pnpm add @cai-ds/tokens 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/tokens@3.0.0/dist/cai-tokens.min.css">

Bringing your own fonts? Load dist/tokens.min.css instead: the same tokens without any @font-face.

Level 2: tokens and core

Components and optional JS behaviors. Core requires tokens, loaded first.

$ pnpm add @cai-ds/tokens @cai-ds/core 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/tokens@3.0.0/dist/cai-tokens.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/core@3.0.0/dist/cai.min.css">

<!-- Optional JS behaviors -->
<script type="module" src="https://cdn.jsdelivr.net/npm/@cai-ds/core@3.0.0/dist/cai.min.js"></script>

Level 3: tokens, core and platform

App-shell patterns. Platform requires both core and tokens.

$ pnpm add @cai-ds/tokens @cai-ds/core @cai-ds/platform 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/tokens@3.0.0/dist/cai-tokens.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/core@3.0.0/dist/cai.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/platform@3.0.0/dist/platform.min.css">

<!-- Optional JS behaviors -->
<script type="module" src="https://cdn.jsdelivr.net/npm/@cai-ds/core@3.0.0/dist/cai.min.js"></script>

Notes

  • npm and pnpm install the required lower layers automatically; Yarn only warns, so list every package as above.
  • Pin exact versions on a CDN and add an integrity hash in production.
  • A console warning tells you when a layer is loaded without the one below it.

Package boundaries

One direction only: each package depends on the ones above it in this list.

@cai-ds/tokens   -> primitives + semantic token contracts (standalone)
      ↓ required by
@cai-ds/core     -> reusable CSS components + optional JS behaviors
      ↓ required by
@cai-ds/platform -> page and app-shell patterns

Platform can use core and tokens; core can use tokens; nothing in tokens or core may use platform. The packages declare this as required peer dependencies, and a console warning tells you when a layer is loaded without the one below it.

Type scale and minimum sizes

Every size is in rem, so text follows the font size the reader sets in the browser, not only page zoom (WCAG 1.4.4). The scale is the same at every viewport width: no breakpoint makes text smaller. Above the 16px base each step is the one before times 1.25, rounded to whole pixels; below it are the readability floors.

  • Body text is never below --cai-text-base (16px), with a line height of 1.5.
  • Secondary and UI text is never below --cai-text-sm (14px).
  • Nothing goes below --cai-text-xs (12px). Sizes relative to their context (kbd, time, output, inline code, captions) are clamped with max() so they cannot fall below the floor inside small text.
  • Form fields use --cai-text-control (core setting): --cai-text-md on desktop, --cai-text-base (16px) at 768px and below and on touch screens, where iOS Safari zooms the page into any smaller field.

Solid fills

Surfaces that carry --cai-text-on-fill use the fill tokens, not the brand or status color directly: --cai-brand-fill, --cai-brand-fill-hover, --cai-brand-fill-active and --cai-color-danger-fill. In light and high contrast they equal the brand and danger colors; in dark mode they are a step darker, because the dark brand is light enough to be read as text and white on it falls below 4.5:1.

Themes and modes

A color mode changes luminosity; a custom theme changes the whole identity. They are independent.

The three base modes ship with the tokens: data-theme="light", "dark" and "high-contrast". Two custom themes ship with core, each with its own light, dark and high-contrast modes set with data-mode:

  • Minimalist (cai-theme-minimalist.css): one system sans throughout, warm neutrals.
  • Vejer (cai-theme-vejer.css): a reading theme inspired by Vejer de la Frontera. ET Book for running text and headings, whitewash and sandstone surfaces, iron-black text, sky-blue links and actions, and every link underlined.
<html data-theme="dark">

<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/core@3.0.0/dist/themes/cai-theme-vejer.min.css">
<html data-theme="vejer" data-mode-icon="dark">
<html data-theme="minimalist" data-mode-icon="high-contrast">

Every theme is measured by pnpm check:contrast in every mode: 4.5:1 for text, 3:1 for disabled text, borders and focus rings.

Make your own theme

A theme overrides semantic tokens, never the primitive scales and never component CSS. Check it against the same contrast minimums: CAI guarantees only the themes it ships.

[data-theme="my-brand"] {
  --cai-brand-primary: #0057ff;
  --cai-brand-hover: #0043c2;
  --cai-surface-page: #f8faff;
  --cai-text-primary: #0d1320;
  --cai-divider: #dbe3f2;
}

Button

components/button.css
Link as button

When to use

To start an action on the current page: save, send, open a dialog. Use the primary variant once per view.

When not to use

To go to another page. Use a link, or a link styled with the button class. Do not use a disabled button to hide an action.

How it works

A native button element with a variant and a size modifier. Without JavaScript it works as any button; inside a form, set the type.

Content guidance

Start with a verb and say the result: "Save changes", "Delete draft". Never "OK", "Submit" or "Click here". Sentence case.

Keyboard and ARIA

Tab to reach it, Enter or Space to press it. The focus ring is the shared 2px ring. No ARIA is needed; add an aria-label only to an icon-only button.

Known issues

None known.

Copy button

components/copy-btn.css JS: clipboard.js
var(--cai-brand-primary)

The button copies the text in its data-copy attribute.

When to use

To copy a short string the reader will paste elsewhere, such as a command or a token name.

When not to use

For long text, or where selecting the text is enough. Never as the only way to get the content.

How it works

A button with data-copy. It needs JavaScript and the Clipboard API, so it is hidden until the script runs; the text it copies is always on the page, selectable.

Content guidance

Name what is copied in the accessible name: "Copy the install command". The visible label is "Copy"; the result is announced in a polite live region.

Keyboard and ARIA

Tab, then Enter or Space. A polite status message announces "Copied to clipboard" or the failure.

Known issues

Needs a secure context (https or localhost) for the Clipboard API; the failure is announced and the text can still be selected.

Tooltip

components/tooltip.css
Tooltip content

When to use

To explain a control whose label is not enough, in a sentence at most.

When not to use

For anything essential, long or interactive. On touch devices there is no hover: put important text on the page.

How it works

CSS only: it opens on hover and on keyboard focus, and stays open while the pointer is over it (WCAG 1.4.13, hoverable).

Content guidance

One short sentence, no links. The control keeps its own accessible name.

Keyboard and ARIA

Opens when the control receives focus, closes when it loses focus. The Escape key does not close it.

Known issues

Partial WCAG 1.4.13: the tooltip cannot be dismissed with Escape without moving focus or the pointer. Keep tooltips non-essential.

Level 3 · @cai-ds/platform

Platform

Page-level patterns built on core: the page shell, skip link, page header, sections, action groups, feature grids, command blocks, the footer and an image frame. The home page is built with them. Every class starts with .cai-platform- and uses semantic tokens only.

Use platform when

  • You build a site or an app with a header, a main area and a footer on every page.
  • You want the same spacing and layout across many pages.
  • You want a skip link, feature grids and action groups without writing the layout yourself.

Use core alone when

  • You only need components such as buttons, forms and cards.
  • You have your own layout system, or a framework that owns the page shell.
  • You build a single widget, not a whole page.

Your own components on top

Style what you add with semantic tokens too, never with the primitive scales, so it follows the color mode and any custom theme.

.my-panel {
  background: var(--cai-surface);
  border: 1px solid var(--cai-divider);
  color: var(--cai-text-primary);
}

.my-panel:hover {
  background: var(--cai-surface-muted);
  border-color: var(--cai-outline);
}

Image

.cai-platform-image, --4x3, --3x2, --1x1, --21x9, --9x16

Ratios: 16:9, --4x3, --3x2, --1x1, --21x9, --9x16.

When to use

To show an image in a box of fixed shape, such as a card cover or an article header, when the image may be missing: content from people or a content system, or a page built before its images exist.

When not to use

For an image that must keep its own shape, such as a chart or a screenshot: the frame crops it. For icons and logos: use an <img> or an SVG at its own size. Never to stand in for an image that carries information: if it is missing, say so in text.

How it works

A <div> of fixed aspect ratio, 16:9 unless a modifier sets another, around a native <picture> with AVIF and WebP sources and a JPEG <img>. The image fills the frame and is cropped to it. A frame with no image shows an abstract placeholder in the colours of the vejer theme, chosen in AVIF, WebP or JPEG with image-set(). In dark mode it shows a night version; high contrast keeps the day version. No JavaScript is involved. While an image loads, or if it fails, the frame shows a flat surface, and a failed image's alt text is drawn on it. Transparent PNG and SVG images sit on that surface too. Without CSS the image shows at its own size. The placeholder files ship in dist/placeholders/: every ratio at 640, 1280 and 1920 pixels on the long side in AVIF and WebP, at 640 and 1280 in JPEG, and two SVGs, day and night, that fit any size. Point your own <picture> at them to show the placeholder on purpose.

Content guidance

Give every real image an alt text that says what it shows, in one plain sentence. If the image is decorative or the text next to it already says the same, use alt="". Never describe the placeholder: it is a background and nothing reads it out. The frame crops the image to its ratio, so keep text and essential detail away from the edges, and describe what stays visible. Set width and height on the <img> to the image's own size so the page does not jump while it loads. Add loading="lazy" only to images below the fold; leave it off a hero or any image visible when the page opens, so it loads at once. Do not put text in images.

Keyboard and ARIA

No interaction of its own. Screen readers announce the <img> by its alt text and skip the placeholder; an empty frame announces nothing. Do not add a role or an aria-label to the frame. If the image is a link, the link takes its name from the alt text, so the alt text must then say where it goes.

Known issues

In forced-colors mode browsers drop the placeholder, and the frame shows a thin border instead. If an image fails to load, some browsers add a broken-image icon next to its alt text. The night version follows a dark mode set on a page or a section, but not a light section inside a dark one.

Show the placeholder on purpose

Point a <picture> at the files in dist/placeholders/, named placeholder-<ratio>-<width>. It is decorative, so its alt text is empty.

<div class="cai-platform-image">

    <source type="image/avif"
      srcset="placeholders/placeholder-16x9-640.avif 640w,
              placeholders/placeholder-16x9-1280.avif 1280w,
              placeholders/placeholder-16x9-1920.avif 1920w"
      sizes="(min-width: 768px) 50vw, 100vw">
    <source type="image/webp"
      srcset="placeholders/placeholder-16x9-640.webp 640w,
              placeholders/placeholder-16x9-1280.webp 1280w,
              placeholders/placeholder-16x9-1920.webp 1920w"
      sizes="(min-width: 768px) 50vw, 100vw">
    <img src="placeholders/placeholder-16x9-1280.jpg"
      srcset="placeholders/placeholder-16x9-640.jpg 640w,
              placeholders/placeholder-16x9-1280.jpg 1280w"
      sizes="(min-width: 768px) 50vw, 100vw"
      width="1280" height="720" alt="" decoding="async">

</div>

For the night version, use placeholder-night- instead. placeholder.svg and placeholder-night.svg fit any size. Add loading="lazy" when the frame is below the fold.

Document root

The root of the page and the container of everything the reader sees. These two are documented as markup; CAI styles them in the document layer.

<body>

MDN reference for the body element

Holds everything a visitor sees on the page. Each page has one, right after the head.

Markup only: this element is not rendered.

HTML

</body>

Styled by elements/document.css, with no class. Layout-neutral until you add o-shell for the sidebar and main layout.

MDN reference for the html element

The outermost tag, wrapping the whole page. Put lang on it so screen readers and translation tools pick the right language, and data-theme to choose the CAI color mode.

Markup only: this element is not rendered.

Styled by elements/document.css, with no class. CAI reads data-theme on this element: light, dark or high-contrast.

Changes the starting point of every relative URL on the page, and can set a default target for links. Use at most one, and place it before any tag that has a URL.

Markup only: this element is not rendered.

      Accessibility statement

      What CAI aims for, what is checked on every change, and what has not been tested. Last reviewed on 8 October 2026.

      Target

      CAI aims to meet WCAG 2.2 level AA, the level that EN 301 549 and the European Accessibility Act refer to. A design system cannot make a service accessible by itself: how you use the components decides the result.

      What is checked on every change

      • An automated scan with axe-core of the home page and this documentation page, in the light, dark and high-contrast modes. A serious or critical finding fails the build.
      • Keyboard use of the sidebar drawer, the modal dialog and the tabs.
      • The pages with JavaScript turned off: content is readable at 320 pixels wide, and no control that needs JavaScript is left on screen doing nothing. The color mode switcher in the page header shows as three radio buttons, which still set the mode.
      • Reduced motion: no transition or animation runs when the visitor asks for less motion.
      • Forced colors: a focused button keeps a visible outline.
      • Contrast of the text written for the home and documentation pages, in all three modes.
      • Contrast of every token pair a component draws, by a script, in the three base modes and in each mode of the shipped custom themes (minimalist and vejer).

      What has not been tested

      • Screen readers. No assistive technology has been used to test this release: NVDA, JAWS, VoiceOver, TalkBack and Orca have not been tried. Nothing here says a component works with them.
      • Speech recognition and screen magnifier software.
      • Zoom to 400 percent by hand. Only the 320 pixel width is measured.
      • Research with disabled people.

      Automated tools find only part of the problems. Treat this list as the gap, and test your own pages.

      Known issues

      • The tooltip cannot be dismissed with the Escape key. This partly fails WCAG 1.4.13 (Content on hover or focus). Keep tooltips non-essential.
      • The modal buttons use the command and commandfor attributes. In a browser without them, and without JavaScript, the open button does nothing.
      • The MIDI player needs JavaScript and Web Audio. Without them it shows a message.
      • On the home and documentation pages, a stored color mode can flash once on load, because no inline script sets it before the first paint.
      • The button of the example form on the home page opens a popover that says nothing was sent; a status region repeats it for screen readers when JavaScript runs. This has not been tested with a screen reader.

      Report a problem

      If something does not work for you, open an issue on GitHub and say what you were trying to do, the browser and the assistive technology you use.
