Example

The preview, and the markup that makes it under it. The width of the frame follows --luz-docs-example-w.

Known issues

None known.

Code Design

Code

Copy the markup

A figure with the preview and, under it, the code. The code is optional:

HTML 
<figure class="luz-docs-example">
  <div class="luz-docs-example__preview">
    <div class="luz-docs-example__frame">
      <button class="luz-btn luz-btn--primary" type="button">Save changes</button>
    </div>
  </div>
  <div class="luz-docs-example__code">
    <pre class="luz-code-block" data-lang="html" tabindex="0" aria-label="Markup of the example"><code>&lt;button class="luz-btn luz-btn--primary" type="button"&gt;Save changes&lt;/button&gt;</code></pre>
  </div>
</figure>

Variants and options

No modifier. The width is a custom property.

Class or propertyEffect
.luz-docs-example
On a <figure>: one framed box with a rounded border on the surface. The preview and the code share it
.luz-docs-example__preview
The live markup, with padding around the frame
.luz-docs-example__frame
Inside the preview: as wide as the preview, or as --luz-docs-example-w says (never wider), and centred. It is a size container
.luz-docs-example__code
Optional, under the preview, across its width, with a rule above. A pre.luz-code-block in it loses its own border
--luz-docs-example-w
The width of the frame. Set it on the frame: style="--luz-docs-example-w: 20rem" is a phone. It defaults to the whole preview

How it works

CSS from @luz-ds/docs on core's code block and highlight.

  • The preview and the code are one frame, so they read as one example. A long line scrolls inside the code block and never widens the figure.
  • The frame's width is min(100%, var(--luz-docs-example-w, 100%)): a width larger than the room does not widen the figure.
  • The frame is a size container (container-type: inline-size). A block button fills the frame, not the window, and a rule of your own can answer to the frame with @container.
  • Write the markup once and show it twice, as a preview and as escaped code: the reader sees what they copy.

Without JavaScript

Nothing changes in the frame. The code block is plain text in a region that scrolls and takes the focus, without the highlight and the copy button of core's script.

Keyboard and ARIA

  • Order: the controls of the preview, then the code block.
  • Code block: keep tabindex="0" and an aria-label on the <pre>: it scrolls, and without them a keyboard user cannot reach it or tell what it is.
  • Preview: it is live, so what is in it works as it does anywhere. A picture that must not be used goes in Do and don't, whose stage is inert.

Design

When to use

Use the example to show a piece and the markup that makes it, in one frame, the code under the preview.

  • A component, a pattern or a snippet that a reader will copy.
  • A piece whose look depends on its width: set the frame's width.

When not to use

Do not use the example to show a mistake or code with nothing to preview.

  • A picture of a mistake goes in Do and don't, which is inert.
  • Code with nothing to show, such as a command, is a plain code block.

Do and don't

Writing the content

  • The sentence before the example says what it shows, in the imperative: "Add the primary class to make the main action."
  • The code is the markup the preview is made of, word for word. Use real words in it, not "Lorem ipsum" and not "Button".
  • Name in the sentence the one class or attribute the example teaches, so the reader knows where to look in the code.
  • Name the code block: "Markup of the example", or "Markup of the primary button" when there are several.

Measured from the token values of each mode, rounded down. Needs is the WCAG 2.2 AA minimum: 4.5:1 for text, 3:1 for focus rings, borders and icons.

  • Focus: the controls of the preview and the code block keep core's ring, 2 px of --luz-focus-ring.
  • Edges: the border of the frame (--luz-divider) is decorative and has no minimum.
  • Width: the frame never passes the room it has, so the page does not scroll sideways at 320px.
