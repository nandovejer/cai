Each template is markup to copy into your site, with your own text in place of the example. They use the classes of core and docs only.

The first is a whole page; the second is one piece that changes at the ends of a sequence. The last section says what is not in the package yet.

Documentation page

A whole page: the skip link, the header, the sidebar, the content with its head, an example and a do and don't pair, the pager and the page foot, then the rail and the footer, on the shell.

  • Load the CSS of tokens, core and docs in that order: Install LUZ has the command. Core's script is optional: it marks the section in view in the rail and closes the drawer when a link is followed.
  • The columns are placed by the shell, so the source stays in reading order: sidebar, content, rail.
  • The links of the sidebar and of the rail are examples. The rail lists the h2 of the page, and its h3 in a nested list.
  • From 80rem the shell always has three tracks. Without the <aside> the third stays empty, so keep the rail on every page of the site. Below 80rem the rail is drawn under the content, before the footer.

First and last page

The first page of a sequence has no previous page and the last has no next one. Leave the other item out: a lone Next stays at the end of the row, and a lone Previous at the start.

  • Do not add a link that leads nowhere to keep two blocks: an empty block is a link that does nothing.
  • If a page is part of two sequences, use one pager and decide which sequence it follows.

What is not here

A documentation site often asks for things the package does not have. They are not faked in the templates above.

  • Search. Use site's search, an optional peer of this package.
  • Syntax highlighting and a copy button on the code. They are core's code block, with its script.
  • A width selector for the example, and live controls that rewrite it. The frame reads --luz-docs-example-w; the control that sets it is yours.
  • A script for "Copy page as Markdown". The rail has the link; copying its target is yours.
  • Versions, translations and a changelog. They are the content of your site.
