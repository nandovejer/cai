Package boundaries

Each package depends on the ones above it in this list, never on the ones below.

The name stands for Consistent Adaptive Identity: one set of tokens that every component reads (consistent), that switches between light, dark and high contrast and reflows with the screen (adaptive), and that your own tokens can replace to carry your brand (identity).

@cai-ds/tokens   -> primitive and semantic tokens (standalone)
      ↓ required by
@cai-ds/core     -> components, bare-element styles, optional JS
      ↓ required by
@cai-ds/site     -> page patterns and the site search
      ↓ required by, each on its own
@cai-ds/landing  -> patterns for a landing page (own version, 0.x)
@cai-ds/cms      -> patterns for a blog, a newspaper or any CMS (own version, 0.x)
  • Landing and cms can use site, core and tokens, never each other; site can use core and tokens; core can use tokens; tokens uses nothing.
  • Tokens, core and site share one version. A package for one kind of site, such as landing or cms, has its own, and names the major of the others it needs.
  • The packages say so as required peer dependencies, and the core and site scripts warn in the console when a level is missing.

CSS layers

Core's CSS comes in native cascade layers (@layer), in ITCSS order, inside one container layer called cai. The six below are the ones that hold its rules; the layers page lists them all, with tokens, site and print. A later layer wins over an earlier one, and any CSS of yours that is not in a layer wins over all of CAI, with no !important. How to order and override them.

packages/core/src/
  settings/_settings.css      cai.settings    motion, z-index, breakpoints
  generic/_reset.css          cai.generic     the reset
  elements/*.css              cai.elements    bare HTML elements, zero specificity
  objects/_objects.css        cai.objects     layout: .o-*
  components/*.css            cai.components  the components: .cai-*
  utilities/_utilities.css    cai.utilities   single-purpose helpers: .u-*
  • The components layer holds 25 components.
  • dist/cai.css holds these six layers and cai.print. Tokens are in cai.tokens, site in cai.site, landing in cai.landing and cms in cai.cms; cai.themes is empty, kept for a look of your own. For a page that needs a few components only, load dist/base.css (settings, reset and elements), then dist/components/<name>.css for each one.
  • Rules for bare elements are wrapped in :where(), so any class wins over them.

The script

One optional entry point, cai.js, starts every behaviour on the page: color mode, copy buttons, dialogs, highlighting, players, tabs and the sidebar.

HTML 
<script type="module" src="https://cdn.jsdelivr.net/npm/@cai-ds/core@3.0.0/dist/cai.min.js"></script>

To load less, import one module and call its init function. See JavaScript modules.

<!doctype html>

<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Sign up – Acme</title>
  <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/tokens@3.0.0/dist/cai-tokens.min.css">
  <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/core@3.0.0/dist/cai.min.css">

<body>
  <main class="o-container">
    <h1>Sign up</h1>
    <form action="/signup/" method="post">
      <div class="cai-field">
        <label class="cai-field__label" for="email">Email</label>
        <input class="cai-input" id="email" name="email" type="email" autocomplete="email" required>
      </div>
      <button class="cai-btn cai-btn--primary" type="submit">Create account</button>
    </form>
  </main>
</body>
</html>
