For one kind of site · @luz-ds/landing

What a landing page needs on top of site, from the feature grid to the blocks of an event page, and how to tell whether you need it.

A landing page is one page that presents a product or an event and asks the visitor to act. This package holds the patterns only that kind of page uses. Everything every site needs, from the page shell to the site header, stays in Site.

  • Every class starts with .luz-landing-, uses semantic tokens only and sits in the cascade layer luz.landing, after site's.
  • It has no script. Load landing.css after the CSS of tokens, core and site: Install LUZ has the command and the CDN tags.
  • It has a version of its own, 0.x while it grows, and needs version ^0.1.0 of tokens, core and site, declared as peer dependencies.
  • The LUZ home page is built with it.

Use landing when

  • You build the page of a product, a service or an event, with features to show side by side.
  • You want blocks to copy for such a page: hero, programme, speakers, tickets, call to action and registration.

Use site alone when

  • Your pages are articles, documentation or an app: a header, the content and a footer.
  • You lay out your own blocks with core's grid objects.
