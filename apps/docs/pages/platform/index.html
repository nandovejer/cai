Page patterns built on core, from the page shell to the site search, and how to tell whether you need them.

A pattern combines components to do a product task: a page shell, a feature grid, a site search. A component is one reusable piece, almost always tied to one HTML element; components are in Components.

  • Every class starts with .cai-platform- and uses semantic tokens only.
  • The CAI home page and these docs are built with them.

Use platform when

  • You build a site or an app with a header, a main area and a footer on every page.
  • You want the same spacing and layout across many pages.
  • You want a skip link, a page header, feature grids and a site search without writing them yourself.

Use core alone when

  • You only need components such as buttons, forms and cards.
  • You have your own layout system, or a framework that owns the page shell.
  • You build a single widget, not a whole page.

Your own components on top

Style what you add with semantic tokens too, so it follows the color mode and any custom theme.

.my-panel {
  background: var(--cai-surface);
  border: 1px solid var(--cai-divider);
  color: var(--cai-text-primary);
}

.my-panel:hover {
  background: var(--cai-surface-muted);
  border-color: var(--cai-outline);
}
