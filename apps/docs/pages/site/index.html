Level 3 · @cai-ds/site

What every site needs above the components, from the page shell to the site search, and how to tell whether you need it.

A piece is here when it needs data of the site (its languages, its search index, its menu) or is page structure that holds other pieces: a page shell, a site header, a section. Everything else is a component, one reusable piece that fits inside anything; components are in Components.

Packages for one kind of site build on this one: landing for a landing page, and later cms for a blog, a newspaper or any CMS, and wordpress on top of cms.

  • Every class starts with .cai-site- and uses semantic tokens only.
  • The CAI home page and these docs are built with them.
  • Not sure which package a piece belongs to? What each package needs lists every piece, with the package it is in.

Use site when

  • You build a site or an app with a header, a main area and a footer on every page.
  • You want the same spacing and layout across many pages.
  • You want a site header, a skip link, a page header and a site search without writing them yourself.

Use core alone when

  • You only need components such as buttons, forms and cards.
  • You have your own layout system, or a framework that owns the page shell.
  • You build a single widget, not a whole page.

Your own components on top

Style what you add with semantic tokens too, so it follows the color mode and any theme of your own.

.my-panel {
  background: var(--cai-surface);
  border: 1px solid var(--cai-divider);
  color: var(--cai-text-primary);
}

.my-panel:hover {
  background: var(--cai-surface-muted);
  border-color: var(--cai-outline);
}
