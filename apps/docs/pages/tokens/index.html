Level 1 · @cai-ds/tokens

Two layers of CSS custom properties. Primitives hold raw values. Semantic tokens give them a role and change with the color mode. Components only ever use semantic tokens.

Layer model

packages/tokens/tokens.json
      -> source of primitives (blue-10..100, gray-10..100, spacing, radius...)

    packages/tokens/dist/cai-tokens.css
      Layer 1: generated primitives
      Layer 2: handwritten semantics per theme (light/dark/high-contrast)

Component token rule

/* Correct: semantic tokens */
    color: var(--cai-text-primary);
    background: var(--cai-brand-primary);
    border-color: var(--cai-divider);

    /* Incorrect: primitive scales */
    color: var(--cai-gray-100);
    background: var(--cai-blue-60);

Solid fills

Surfaces that carry --cai-text-on-fill use the fill tokens, not the brand or status color directly: --cai-brand-fill, --cai-brand-fill-hover, --cai-brand-fill-active and --cai-color-danger-fill. In light and high contrast they equal the brand and danger colors; in dark mode they are a step darker, because the dark brand is light enough to be read as text and white on it falls below 4.5:1.
