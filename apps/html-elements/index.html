HTML elements

Every current HTML element: 116 elements in 14 categories, each with a live example, the markup to copy and a note on how CAI styles it. The list follows MDN. Deprecated elements are left out on purpose.

!
Beta
CAI is in beta. The tokens, components and patterns work and are tested, but names, classes and behavior can still change before the stable release. Pin an exact version and read the changelog before you upgrade.

How to read a card

  • Live example. The real element, styled by CAI right now. Switch the color mode above to check it.
  • Markup. The exact code of the example. The copy button copies what you see.
  • CAI note. Whether the element is styled with no class, through a component class, or left to the browser.

Rules that style bare elements have zero specificity: any .cai-* class, or a rule of your own, wins.

Document root

The root of the page and the container of everything the reader sees. These two are documented as markup; CAI styles them in the document layer.

<body>

MDN reference for the body element

The visible content of the document. There is exactly one.

Markup only: this element is not rendered.

HTML 
<body class="o-shell">
  <a class="cai-platform-skip-link" href="#main-content">Skip to main content</a>
  <main id="main-content">…</main>
</body>

Styled by elements/document.css, with no class. Layout-neutral until you add o-shell for the sidebar and main layout.

<html>

MDN reference for the html element

The root element. Everything else in the document is a descendant of it. Set lang for screen readers and translation, and data-theme for the CAI color mode.

Markup only: this element is not rendered.

HTML 
<!DOCTYPE html>
<html lang="en" data-theme="light">
  <head>…</head>
  <body>…</body>
</html>

Styled by elements/document.css, with no class. CAI reads data-theme on this element: light, dark or high-contrast.

Document metadata

Information about the page for browsers, search engines and scripts. None of it is rendered, so these cards show the markup only.

<base>

MDN reference for the base element

Sets the base URL for every relative URL in the page, and a default target for links. There can be one, and it must come before any URL it affects.

Markup only: this element is not rendered.

HTML 
<base href="https://example.com/app/" target="_blank">

CAI adds no style: the browser look is kept. It also rewrites hash-only links such as href="#top", so use it with care.

<head>

MDN reference for the head element

Holds the metadata of the page: title, character set, stylesheets and scripts. It is never rendered.

Markup only: this element is not rendered.

HTML 
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>My page</title>
</head>

CAI adds no style: the browser look is kept.

<link>

MDN reference for the link element

Relates the page to an external resource, most often a stylesheet. Load tokens first, then core, then platform.

Markup only: this element is not rendered.

HTML 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/tokens@3.0.0/dist/cai-tokens.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/core@3.0.0/dist/cai.min.css">

CAI adds no style: the browser look is kept.

<meta>

MDN reference for the meta element

Machine-readable information that no other element covers: character set, viewport, description, color scheme.

Markup only: this element is not rendered.

HTML 
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<meta name="description" content="A vanilla design system in plain CSS.">

CAI adds no style: the browser look is kept.

<style>

MDN reference for the style element

Holds CSS for the document. Prefer a linked stylesheet; use this for a small amount of critical or generated CSS.

Markup only: this element is not rendered.

HTML 
<style>
  .banner { padding: var(--cai-space-05); }
</style>

CAI adds no style: the browser look is kept.

<title>

MDN reference for the title element

The title of the page: shown in the tab, in bookmarks and in search results, and read first by screen readers.

Markup only: this element is not rendered.

HTML 
<title>HTML elements: CAI Design System</title>

CAI adds no style: the browser look is kept.

Content sectioning

The outline of a page: landmarks, headings and the regions between them. Most are neutral boxes whose value is the meaning they give to assistive technology.

<address>

MDN reference for the address element

Contact information for the nearest article or the whole page. The browser makes it italic; CAI makes it upright and secondary.

hello@example.com

</address>

<main>

MDN reference for the main element

The dominant content of the page. A page has one visible main, so this card shows the markup only: the page you are reading is already inside one.

Markup only: this element is not rendered.

HTML 
<main id="main-content" tabindex="-1">
  <h1>Page title</h1>
  …
</main>

CAI adds no style: the browser look is kept. tabindex="-1" lets the skip link move focus into it.

<nav>

MDN reference for the nav element

A block of navigation links. Label each one when there is more than one, so screen reader users can tell them apart.

Home · Docs · Platform
HTML

  <a href="#">Home</a> ·
  <a href="#">Docs</a> ·
  <a href="#">Platform</a>
</nav>

CAI adds no style: the browser look is kept. For breadcrumbs and the sidebar, CAI has components with their own classes.

<search>

MDN reference for the search element

A region that holds a search or filtering form. It is a search landmark with no role attribute needed.
HTML 
<search>
  <form action="#">
    <label for="d-search">Search the docs</label>
    <input class="cai-input" id="d-search" type="search" name="q">
    <button class="cai-btn cai-btn--primary" type="submit">Search</button>
  </form>
</search>

CAI adds no style: the browser look is kept.

    <dialog>

    MDN reference for the dialog element

    A native dialog. Opened with showModal() it is modal: it traps focus, shows a backdrop and closes with Escape. The button here opens it with no script.

    A native dialog

    Press Escape or the button to close it.
    HTML 
    <button class="cai-btn cai-btn--primary" type="button" command="show-modal" commandfor="d-dialog">Open dialog</button>
<dialog id="d-dialog" aria-labelledby="d-dialog-title">
  <h4 id="d-dialog-title">A native dialog</h4>
  <p>Press Escape or the button to close it.</p>
  <form method="dialog">
    <button class="cai-btn cai-btn--primary">Close</button>
  </form>
</dialog>

    Styled by elements/interactive.css, with no class. A dialog with no class gets a surface and its centering back. .cai-modal is the component with a header, body and footer.

    <geolocation>

    Web Components

    The two HTML elements behind custom elements: a template that is parsed but not rendered, and a slot that shows light-DOM content inside a shadow tree.

    <slot>

    MDN reference for the slot element

    A placeholder inside a shadow tree where the content of the host element is shown. A named slot takes only the content that asks for it.

    Hello from the light DOM This text fills the default slot.
    HTML 
    <template id="d-slot-template">
  <style>
    article { padding: var(--cai-space-04); border: 1px solid var(--cai-border-subtle); }
    h4 { margin-bottom: var(--cai-space-02); }
  </style>
  <article>
    <h4><slot name="title">Untitled</slot></h4>
    <slot>No content.</slot>
  </article>
</template>

<demo-card>
  <span slot="title">Hello from the light DOM</span>
  This text fills the default slot.
</demo-card>

    CAI adds no style: the browser look is kept. The custom element takes a few lines of script. Design tokens cross the shadow boundary, so the card follows the color mode.
