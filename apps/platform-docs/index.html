@cai-ds/platform

App-shell patterns and higher-level layout primitives built on top of CAI core. Use Platform when you are building a web application with a consistent page structure — not when you only need individual components.

Installation
Platform depends on @cai-ds/tokens and @cai-ds/core. Load all three in order.
HTML (CDN)
<!-- 1. Tokens (always first) -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/tokens/dist/cai-tokens.css">

<!-- 2. Core components -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/core/dist/cai.css">

<!-- 3. Platform app-shell patterns -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/platform/dist/platform.css">

<!-- Optional: Core JS behaviors -->
<script type="module" src="https://cdn.jsdelivr.net/npm/@cai-ds/core/dist/cai.js"></script>

When to use Platform
Platform primitives are opinionated by design. If the pattern doesn't map to your use case, compose with core components directly instead.
Use Platform when
  • Building a web app with a persistent header, main content area, and footer
  • You need consistent spacing and layout across multiple app pages
  • You want skip-links, feature grids, and action containers without writing the scaffolding yourself
  • Both @cai-ds/tokens and @cai-ds/core are already in your project
Skip Platform when
  • You only need individual UI components (buttons, forms, cards) — use @cai-ds/core alone
  • You have your own layout system and only need tokens
  • You are embedding CAI into an existing framework layout (Next.js App Shell, etc.)
  • You are building a standalone widget, not a full-page app
Architecture
Three layers with unidirectional dependencies. A lower layer never imports from a higher one.
Dependency chain
@cai-ds/tokens   ←  primitives + semantic theme variables
      ↓
@cai-ds/core     ←  generic reusable components (buttons, forms, cards…)
      ↓
@cai-ds/platform ←  app shells, layout patterns, higher-level primitives
Rule

Platform can import from core and tokens. Core can import from tokens. Nothing in core or tokens may import from platform. This rule is enforced by convention — there is no bundler that enforces it at build time.

Class reference
All Platform classes are prefixed .cai-platform-. They consume semantic tokens only — never primitive color scales.
Page structure
Class Element Description
.cai-platform-page <body> Root grid (header / 1fr / footer). Sets min-height: 100vh.
.cai-platform-page--gradient <body> Modifier. Adds a radial brand-subtle gradient at the top-left corner. Use on marketing or landing pages.
.cai-platform-skip-link <a> Visually hidden until focused. Jumps to #main-content. Required for keyboard accessibility.
.cai-platform-main <main> Main content area. Grid with gap: --cai-space-10 between sections. Combine with .o-container for horizontal centering.
.cai-platform-content <div> / <main> Padded content wrapper with max-width cap. For app-shell layouts where the sidebar handles its own width.
.cai-platform-section <section> Grid container with vertical gap between child elements. Use as the direct child of .cai-platform-main.
Header & footer
Class Element Description
.cai-platform-page-header <div> / <header> Hero-style page header block with bottom margin. Contains a title and optional lead.
.cai-platform-page-header__title <h1> Heading: heading font, size 3xl, weight 300, tight letter-spacing.
.cai-platform-page-header__lead <p> Subtitle: secondary text color, max-width 600px.
.cai-platform-footer <footer> Flex row (space-between). Includes a top border and vertical padding. Collapses to column on mobile. Combine with .o-container.
Content patterns
Class Element Description
.cai-platform-actions <div> Flex row with wrapping and gap for CTA button groups. Collapses to column on mobile <480px.
.cai-platform-feature-grid <div> 2-column grid for feature cards. Collapses to 1 column on mobile. Place .cai-card elements as direct children.
.cai-platform-command-block <div> Installation/CLI command display. Dark background, mono font. Flex row: command on left, copy button on right.
.cai-platform-command-block__cmd <code> The command text. Mono font, wraps on overflow.
.cai-platform-command-block__prefix <span> Shell prefix character ($, pnpm, etc.). Secondary color, non-selectable.

Form behavior (range + output)
const range = document.getElementById("experience");
const out = document.getElementById("experience-out");

if (range && out) {
  const sync = () => {
    out.value = range.value;
    range.setAttribute("aria-valuenow", range.value);
  };

  range.addEventListener("input", sync);
  sync();
}

Source & build
Platform source lives in packages/platform/src/. Never edit dist/ directly.
File layout
packages/platform/
├── src/
│   ├── components/
│   │   └── _components.css   ← all .cai-platform-* classes
│   ├── index.css             ← @import entry
│   └── platform.js           ← reserved entrypoint (no-op)
└── dist/
    ├── platform.css          ← generated, do not edit
    └── platform.js           ← generated, do not edit
Regenerate dist after editing src
$ pnpm platform:build
