        Known issues

        Code Design

        Code

        Copy the markup

        HTML 
        <button class="cai-btn cai-btn--primary" type="button">Save changes</button>

        A link that goes somewhere, with the look of a button:

        HTML 
        <a class="cai-btn cai-btn--outline" href="/pricing/">See the plans</a>

        Variants and options

        Combine .cai-btn with one variant and, if needed, one size.

        Class or attributeEffect
        .cai-btn--primary
        Brand fill: the main action of the view
        .cai-btn--secondary
        Strong neutral surface: a second action
        .cai-btn--outline
        Brand text and border, no fill
        .cai-btn--ghost
        Brand text only: a low-priority action
        .cai-btn--danger
        Danger fill: an action that deletes or cannot be undone
        .cai-btn--sm
        36 px high, small text
        .cai-btn--lg
        56 px high, base text
        disabled
        Muted text, dashed border, no pointer events

        The default height is 44 px. An <svg> inside the button is drawn at 16 × 16 px, before or after the label.

        How it works

        A native <button> (or <a>) with classes from components/button.css. No JavaScript.

        • Set type="button" unless the button submits a form; the default type is submit.
        • The height is a minimum: the label can grow with the reader's font size.

        Without JavaScript

        A button works like any native button: it submits its form or runs nothing. What it does on click is up to your script.

        Keyboard and ARIA

        Tab reaches the button; Enter or Space presses it. A link styled as a button answers to Enter only, as every link does.

        • No ARIA is needed: the visible label is the name.
        • An icon-only button needs a name: aria-label="Close", and the icon aria-hidden="true".
        • A disabled button is skipped by Tab and screen readers may not find it: prefer an enabled button that explains what is missing.

        Contrast and focus are in the Design tab.

        Design

        When to use

        Use a button to start an action on the current page: save, send, delete, open a dialog.

        • One primary button per view, for the action most people take.
        • Secondary, outline or ghost buttons for the other actions.

        When not to use

        Do not use a button to go to another page: use a link, styled as a button only when it is the main call to action.

        • For several related actions in a row, use an action group.
        • Do not disable a button to hide an action the reader cannot take yet: say why instead.

        Do and don't

        Writing the content

        Start with a verb and say the result: "Save changes", "Delete draft".

        • Never "OK", "Submit" or "Click here".
        • Sentence case, two or three words, no full stop.
        • Use the same words for the same action everywhere.

        Tokens it uses

        The 24 tokens that components/button.css reads, by family. Each family links to its page, with the values in every mode. In Figma they are variables with the same names: see Tokens in Figma.

        Color
        --cai-brand-fill, --cai-brand-fill-active, --cai-brand-fill-hover, --cai-brand-primary, --cai-brand-subtle, --cai-color-danger-fill, --cai-focus-ring, --cai-outline, --cai-surface-strong, --cai-text-disabled, --cai-text-on-fill, --cai-text-primary
        Spacing and sizing
