        Example

  padding: var(--cai-space-md);
  color: var(--cai-text-primary);
  background: var(--cai-surface);
}
        <button
  class="cai-btn cai-btn--primary"
  type="button">
  Save changes
</button>

  from "@cai-ds/core/midi";

const player = await MidiPlayer.load(url);
player.play();

        Inline code looks like var(--cai-text-primary) inside a sentence.

        Syntax colours in the three modes

        CAI's own scheme: keywords stay ink and bold, colour goes to what the author wrote (names, properties, values), comments step back in italic. No red, because red means error. Each colour keeps 4.5:1 or more on the block, 7:1 or more in high contrast.

        TokenClassWhat it marks
        --cai-code-comment
        .tok-comment
        Comments in every language. Muted and italic.
        --cai-code-keyword
        .tok-keyword
        JavaScript and shell keywords, CSS at-rules and !important, the HTML doctype. Ink and bold, no colour.
        --cai-code-name
        .tok-name
        HTML tags, CSS selectors and functions, JavaScript function and class names, shell commands.
        --cai-code-property
        .tok-property
        HTML attributes, CSS properties and custom properties, JSON keys, shell flags and variables.
        --cai-code-string
        .tok-string
        Quoted strings in every language, HTML attribute values.
        --cai-code-literal
        .tok-literal
        Numbers and units, hex colours, true, false, null, HTML entities.

        Known issues

        The highlighter is a set of patterns, not a parser: JSX tags, the contents of HTML style and script elements and unquoted attribute values stay plain. The colours are decoration only: assistive technology reads the code the same way.

        Copy the markup

        HTML 
        <pre class="cai-code-block" data-lang="css" tabindex="0" role="region" aria-label="Panel styles"><code>.panel {
  color: var(--cai-text-primary);
}</code></pre>
        HTML 
        <p>Set the colour with <code class="cai-code-inline">--cai-text-primary</code>.</p>
        JS 
        import { initHighlight } from "@cai-ds/core/highlight";
initHighlight();

        Variants and options

        Two classes, and the language in an attribute.

        Class or attributeEffect
        .cai-code-block
        A block on the muted surface, mono font, scrolls sideways when a line is long
        .cai-code-inline
        Code inside a sentence, in the code colour
        data-lang
        The language: html, css, js, jsx, json, bash, sh or shell. Shown as a badge in the corner. Any other value is shown, not highlighted

        How it works

        A <pre> with a <code> inside, styled by components/code.css. Highlighting is optional, from highlight.js.

        • highlightBlock(pre) colours one block: it wraps the code in six .tok-* classes, one per --cai-code-* token.
        • initHighlight() does it for every pre.cai-code-block, adds an aria-label to a block that has none ("CSS example"), and adds a copy button inside each block. Core gives that button no position: place it with your own CSS, or call highlightBlock() alone. cai.js runs initHighlight().
        • In forced colors every colour becomes the system text colour; bold keywords and italic comments stay.

        Without JavaScript

        The block is plain, readable text in one colour. Nothing is lost but the colours.

        Keyboard and ARIA

        A block can be wider than the screen, so it must take focus: Tab reaches it and the arrow keys scroll it.

        • tabindex="0", role="region" and an aria-label that names the code, so the focus stop has a name.
        • Inline code needs nothing.

        Contrast and focus are in the Design tab.

        Design

        When to use

        Use a code block for code or terminal output the reader may read or copy, and inline code for names inside a sentence.

        When not to use

        Do not use a code block for a long file or for text that is not code.

        • For one command the reader runs, use a command block, which has a copy button.
        • For a whole file, link to the source.
        • For a key the reader presses, use <kbd>.

        Do and don't

        Writing the content

        Show code that works when it is pasted.

        • Name each block in its aria-label: what the code is, not "Code".
        • Set data-lang; use text for output that is not code.
        • Keep lines short: a long line makes the reader scroll sideways.

        • Not colour alone: keywords are bold and comments italic, so the syntax still reads without the colours.
