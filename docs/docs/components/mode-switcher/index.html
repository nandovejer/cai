        Color mode switcher

        components/mode-switcher.css JS: theme.js

        Lets readers choose light, dark or high contrast: radios that work without JavaScript, or one button that cycles.

        Example

        Color mode (specimen)

        The radio group, disabled here so it does not change this page. The working switcher, in the cycle variant, is in this page's footer: one button with the icon of the current mode.

        Known issues

        A stored color mode can flash once on load: no inline script sets it before the page is drawn, by design.

        Code Design

        Code

        Copy the markup

        HTML 
        <fieldset class="cai-mode-switcher">
  <legend class="cai-mode-switcher__label">Color mode</legend>
  <label class="cai-mode-btn" data-theme="light"><input class="cai-mode-btn__input" type="radio" name="cai-theme" value="light" checked>Light</label>
  <label class="cai-mode-btn" data-theme="dark"><input class="cai-mode-btn__input" type="radio" name="cai-theme" value="dark">Dark</label>
  <label class="cai-mode-btn" data-theme="high-contrast"><input class="cai-mode-btn__input" type="radio" name="cai-theme" value="high-contrast">High contrast</label>
</fieldset>

        The cycle variant: the same radios, an icon in each label, and a button with one icon per mode.

        HTML 
        <fieldset class="cai-mode-switcher cai-mode-switcher--cycle">
  <legend class="cai-mode-switcher__label">Color mode</legend>
  <button class="cai-mode-cycle" type="button" aria-label="Change color mode">
    <svg class="cai-mode-btn__icon" data-mode-icon="light" viewBox="0 0 24 24" aria-hidden="true">…</svg>
    <!-- the same for data-mode-icon="dark" and "high-contrast" -->
  </button>
  <span class="cai-mode-cycle__status" role="status"></span>
  <label class="cai-mode-btn" data-theme="light">
    <input class="cai-mode-btn__input" type="radio" name="cai-theme" value="light" checked>
    <svg class="cai-mode-btn__icon" viewBox="0 0 24 24" aria-hidden="true" focusable="false">…</svg>
    Light
  </label>
  <!-- the same for dark and high-contrast -->
</fieldset>
        JS 
        import { initThemeSystem, initThemeCycle } from "@cai-ds/core/theme";
initThemeSystem();
initThemeCycle();

        Variants and options

        Class or attributeEffect
        .cai-mode-switcher
        The radio group, as a row of buttons; the checked one is filled
        .cai-mode-switcher--cycle
        One button instead of the radios, when scripting is on
        .cai-mode-cycle
        The cycle button; shows the icon whose data-mode-icon matches the checked radio
        .cai-mode-cycle__status
        A hidden live region for the new mode; added by the script if missing
        name="cai-theme"
        The radio name the tokens and theme.js listen to

        How it works

        A native radio group, styled by components/mode-switcher.css. The radios are the control and the source of truth.

        • The tokens re-scope the page from the checked radio with :root:has(), so choosing a mode works with no script.
        • initThemeSystem() from theme.js sets data-theme on <html>, stores the choice under cai-theme in localStorage, and follows the system's dark setting until the reader picks a mode.
        • initThemeCycle() turns each --cycle group into one button. Each press checks the next mode and fires its change event, so whatever listens to the radios applies it. It adds the button if the markup has none.
        • cai.js runs both.

        Without JavaScript

        The three radios show, even in the cycle variant, and choosing one changes the mode of the page. The choice is not remembered on the next page.

        Keyboard and ARIA

        Radios: Tab reaches the group, the arrow keys choose a mode.

        • The cycle button: Tab reaches it, Enter or Space moves to the next mode.
        • Its name says what it does and the current mode: "Change color mode. Current: Dark".
        • A polite status announces the new mode: "Color mode: Dark".

        Contrast and focus are in the Design tab.

        Design

        When to use

        Offer a color mode switcher on every page of a site, in the same place, so readers can pick the mode they read best in.

        • The radio group where there is room, such as a settings page or a sidebar footer.
        • The cycle variant where space is short, such as a header or a page footer.

        When not to use

        Do not use the cycle variant where readers compare the modes: the radio group shows all three at once.

        • Do not hide it on a settings page only: a reader who cannot read the page cannot find the setting.

        Do and don't

        Writing the content

        Call the group "Color mode" and the modes "Light", "Dark" and "High contrast".

        • Each mode keeps its visible name next to its icon, so the radios read without the icons.
