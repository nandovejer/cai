        Classless styles

        classless.css

        The look of a button, a text field, a select and a table on the bare element, inside one element you mark, for markup you cannot add classes to.

        On this page
        • What it is
        • Loading it
        • What each element becomes
        • How it stays out of the way
        • Limits

        What it is

        One extra file, classless.css, that gives a bare button, input, textarea, select and table the look of the CAI component, inside an element that has data-cai-classless. It is for markup you do not control: a Markdown file, a CMS, a form from a library.

        It is not in cai.css, and it does nothing until you load it and mark a zone. A page that does not load it is exactly what it was.

        Loading it

        <link rel="stylesheet" href="@cai-ds/tokens/cai-tokens.css">
<link rel="stylesheet" href="@cai-ds/core/css">
<link rel="stylesheet" href="@cai-ds/core/classless.css">

<!-- the whole page -->
<body data-cai-classless>

<!-- or only the rendered content -->
<article data-cai-classless>…</article>
        • It declares the layer order itself, as every file does, and writes in cai.elements. A .cai-* class is in cai.components and wins by order.
        • Put the attribute on <body> or an element inside it. The elements it styles are its descendants.
        • Size: about 1.5 kB min+gzip, with a budget of its own (3 kB).

        What each element becomes

        Bare element, and the component it copies
        ElementLooks likeLeft out
        button, input of type button, reset
        .cai-btn .cai-btn--secondary
        Sizes and the other variants: add the class
        button type="submit", input type="submit"
        .cai-btn .cai-btn--primary
        A button with no type is a submit button to the browser, but not here: say type="submit"
        input of type text, email, password, search, tel, url, number, date, time, datetime-local, month, week; textarea
        .cai-input, .cai-input--textarea
        The label, helper and error of .cai-field
        select
        The closed box of .cai-select
        The styled open list, where the browser has appearance: base-select: that is .cai-select
        table, with its caption, th and td
        .cai-table
        Scrolling and stacking: they need a wrapper and data-label

        Not styled, on purpose: checkbox, radio, range, color, file and hidden inputs have a native control of their own, and a table is never given display: block or a scroll box, which makes some screen readers lose its table semantics.

        How it stays out of the way

        • Specificity zero. Every selector is inside :where(), so any class of yours, in any layer, wins.
        • A CAI class is left alone. An element whose class contains cai- belongs to its component: a .cai-copy-btn inside the zone keeps its own look.
        • A copy, kept honest. The declarations are those of the components. A test compares each bare element with its component, property by property, and fails when one drifts.
        • Everything else about it is the same: the three color modes, focus ring, right-to-left text and forced colors work as in the component.

        Limits

        • A color mode on the same element. The date picker and the select take their color scheme from a data-theme on an ancestor of the zone, as the components do: set data-theme on <html>, not on the zone.
        • Checked by script, not by hand. The parity test passes in Chromium, Firefox 155 and WebKit 26.6, on Linux. Forced colors do not exist in Safari, so that case is checked in Chromium and Firefox only.
        • Not a component. It has no page in the components gallery and no states of its own. If you can add a class, use the component: it has the variants, sizes and documentation.
