        Cascade layers

        How CAI sits in your cascade: one layer called cai, the order to declare, and how to override it with no !important.

        On this page
        • Declare the order first
        • What is inside cai
        • CSS without a layer wins
        • Override CAI
        • Why one container layer
        • Loading with @import

        Declare the order first

        All of CAI's CSS is inside one cascade layer, cai. Put it between your reset and your own styles, and declare that order before any stylesheet loads.

        @layer reset, cai, app;
        • The order of layers is the order in which their names first appear. A statement like this one, before everything else, fixes it.
        • In HTML, put it in a <style> before the <link> elements. In a stylesheet, make it the first line, before any @import of CAI.
        • A later layer wins over an earlier one. So app wins over cai, and cai over reset.
        • You do not have to use these names. Use whatever layers you have: cai is the only name CAI adds.

        Layers, and names with a dot such as cai.components, work in every current browser and have been available since March 2022 (MDN).

        What is inside cai

        Core and the other packages put their rules in their own layers inside cai. They are listed here from first to last: a layer lower in the table wins over the ones above it.

        LayerPackageWhat it holds
        cai.tokens
        tokens
        The --cai-* custom properties
        cai.themes
        core
        Your own looks (only custom properties; make one). CAI ships none: its default look is in cai.tokens
        cai.settings
        core
        Motion, z-index and breakpoint settings
        cai.generic
        core
        The reset
        cai.elements
        core
        Bare HTML elements, at specificity 0
        cai.objects
        core
        Layout objects: .o-*
        cai.components
        core
        The components: .cai-*
        cai.utilities
        core
        Single-purpose helpers: .u-*. They win over components by order, not by !important
        cai.platform
        platform
        The page patterns: .cai-platform-*
        cai.print
        core
        What changes on paper, inside @media print: Print styles. Last, so it wins over the screen styles of core and platform

        Every file CAI publishes repeats the order of this list first, so it is the same whichever file a page loads first. These names are public: renaming one is a breaking change.

        CSS without a layer wins

        Styles that are not in any layer win over every layer, whatever the order in the source. So a plain rule of yours beats cai, and it also beats your own app layer.

        • If your CSS is not in layers at all, nothing changes for you: it already wins over CAI, with no !important.
        • If you use layers, keep your rules in one: a plain rule that you forgot to put in a layer will override your own layers.
        • A plain rule is the one place a layer order does not help. Put an override in app or in no layer at all, and know which one you chose.

        Override CAI

        Three overrides, from the smallest. Each wins over CAI because app comes after cai.

        @layer reset, cai, app;

@layer app {
  /* A token: every component that reads it follows */
  :root {
    --cai-brand-fill: #0b5a8c;
  }

  /* A component: your rule, in your layer */
  .cai-btn {
    min-height: 3rem;
  }

  /* A platform pattern */
  .cai-platform-section {
    padding-block: 4rem;
  }
}
        • Prefer tokens. A token changes every component that reads it, in the mode it is set for. Check the colors you set with the contrast check.
        • No !important and no longer selectors are needed: layer order decides first, and specificity only counts inside one layer.
        • Keep a color override in the right mode: :root in app wins over CAI's dark mode too. Set the token per mode, for example in [data-theme="dark"].

        Why one container layer

        CAI's layers used to be six top-level names: settings, generic, elements, objects, components and utilities. They are short and common, and other tools use some of the same names. A page that loaded one of them next to CAI merged its components or utilities with CAI's, and the order between them was an accident.

        • Inside cai, CAI's layer names cannot meet yours.
        • One name orders all of CAI: you place cai once, and you do not have to know what is inside.
        • It works from a <link> or a CDN, where a layer cannot be added from the outside.

        You can still put your own layer between two of CAI's by naming them in the first statement: @layer cai.components, mine, cai.utilities;.

        Loading with @import

        With a bundler that resolves package names, or with paths to the files, load them as they are. Do not add layer(cai) to the import: the files already declare their layers inside cai, and wrapping them would nest the names as cai.cai.components.

        @layer reset, cai, app;

@import url("@cai-ds/tokens/css");
@import url("@cai-ds/core/css");
@import url("@cai-ds/platform/css");

        Your own stylesheet imports a file after the statement, so the order is set before CAI loads.
