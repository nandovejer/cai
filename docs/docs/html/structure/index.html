        Build the big blocks of a page: landmarks, headings and the sections between them. They look like plain boxes; their value is what they tell assistive technology.

        <address>

        MDN reference for the address element

        How to reach the people behind the nearest article or the whole page: an email, a phone number, a profile link. Not for any postal address in the text. Browsers make it italic; CAI makes it upright and secondary.

        Ana García
        Calle Mayor 1, Cádiz
        hello@example.com
        HTML 
        <address>
  Ana García<br>
  Calle Mayor 1, Cádiz<br>
  <a href="mailto:hello@example.com">hello@example.com</a>
</address>

        Styled by elements/sections.css, with no class.

        <article>

        MDN reference for the article element

        A piece that would still make sense if you lifted it out and published it somewhere else: a blog post, a product card, a comment.

        Release notes

        Version 3.1 styles the elements that had no look of their own.

        HTML 
        <article>
  <h4>Release notes</h4>
  <p>Version 3.1 styles the elements that had no look of their own.</p>
</article>

        CAI adds no style: the browser look is kept. Neutral box. Give it a class such as cai-card when you want a surface.

        <aside>

        MDN reference for the aside element

        Content beside the main flow that a reader can skip without losing the thread: a sidebar, a pull quote, related links. At the top level of the page it is a complementary landmark.

        Related: Design tokens

        HTML 
        <aside aria-label="Related">
  <p>Related: <a href="#">Design tokens</a></p>
</aside>

        CAI adds no style: the browser look is kept.

        <footer>

        MDN reference for the footer element

        Closing details for the page, or for the nearest article or section: who wrote it, copyright, related links.

        © 2026 CAI Design System
        HTML 
        <footer>
  <small>© 2026 CAI Design System</small>
</footer>

        CAI adds no style: the browser look is kept.

        <h1>

        MDN reference for the h1 element

        The top heading, naming what the page is about. Use one per page. CAI sets every heading in the serif heading font, light weight and tight tracking.

        Heading level 1

        HTML 
        <h1>Heading level 1</h1>

        Styled by elements/sections.css, with no class. Hidden from assistive technology here, so this page keeps a single h1 and a correct outline. The markup below is what to copy.

        <header>

        MDN reference for the header element

        The opening of the page, or of the nearest article or section: a title, a logo, a search box, the main navigation.

        Getting started

        Three layers, adopted in order.

        HTML 
        <header>
  <h4>Getting started</h4>
  <p>Three layers, adopted in order.</p>
</header>

        CAI adds no style: the browser look is kept.

        <hgroup>

        MDN reference for the hgroup element

        Keeps a heading and its subtitle or tagline together, so the extra line is not taken for a heading of its own. CAI sets the paragraph in the secondary color.

        Tokens

        Variables for every design decision.

        HTML 
        <hgroup>
  <h4>Tokens</h4>
  <p>Variables for every design decision.</p>
</hgroup>

        Styled by elements/sections.css, with no class.

        <main>

        MDN reference for the main element

        Wraps what is unique to this page, without the header, navigation and footer that repeat on every page. Only one main can be visible, so this card shows the markup only: the page you are reading is already inside one.

        Markup only: this element is not rendered.

        HTML 
        <main id="main-content" tabindex="-1">
  <h1>Page title</h1>
  …
</main>

        CAI adds no style: the browser look is kept. tabindex="-1" lets the skip link move focus into it.

        <nav>

        MDN reference for the nav element

        Wraps the links people use to move around the site or the page. When a page has more than one, give each a label so screen reader users can tell them apart.

        Home · Docs · Platform
        HTML 
        <nav aria-label="Example navigation">
  <a href="#">Home</a> ·
  <a href="#">Docs</a> ·
  <a href="#">Platform</a>
</nav>

        CAI adds no style: the browser look is kept. For breadcrumbs and the sidebar, CAI has components with their own classes.

        <search>

        MDN reference for the search element

        Wraps a search or filter form, and screen readers then list it as a search landmark. No role attribute needed.
        HTML 
        <search>
  <form action="#">
    <label for="d-search">Search the docs</label>
    <input class="cai-input" id="d-search" type="search" name="q">
    <button class="cai-btn cai-btn--primary" type="submit">Search</button>
  </form>
</search>

        CAI adds no style: the browser look is kept.

        <section>

        MDN reference for the section element

        Groups the content under one heading when no more specific element fits. It becomes a landmark only when you give it an accessible name.

        Installation

        Add the tokens first, then the core.

        HTML 
        <section>
  <h4>Installation</h4>
  <p>Add the tokens first, then the core.</p>
</section>

        CAI adds no style: the browser look is kept.
