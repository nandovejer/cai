Everything in the system on one page: how to install it, the tokens, every core component and platform pattern with its usage guidance, every HTML element as CAI styles it, and the accessibility statement. Every example is rendered live with the CSS you install.

!
Beta
Names, classes and behavior can still change before the stable release. Pin an exact version and read the changelog before you upgrade.

Installation

Three layers, adopted in order. Stop at the level you need: each layer requires the ones below it and nothing above it.

Level 1: tokens only

CSS custom properties (primitives + light, dark and high-contrast semantics) and one MIT-licensed font, ET Book, for headings. The vejer identity also sets running text in it. Text and code use the system fonts. No other CAI package needed.

$ pnpm add @cai-ds/tokens 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/tokens@3.0.0/dist/cai-tokens.min.css">

Bringing your own fonts? Load dist/tokens.min.css instead: the same tokens without any @font-face.

Level 2: tokens and core

Components and optional JS behaviors. Core requires tokens, loaded first.

$ pnpm add @cai-ds/tokens @cai-ds/core 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/tokens@3.0.0/dist/cai-tokens.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/core@3.0.0/dist/cai.min.css">

<!-- Optional JS behaviors -->
<script type="module" src="https://cdn.jsdelivr.net/npm/@cai-ds/core@3.0.0/dist/cai.min.js"></script>

Level 3: tokens, core and platform

App-shell patterns. Platform requires both core and tokens.

$ pnpm add @cai-ds/tokens @cai-ds/core @cai-ds/platform 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/tokens@3.0.0/dist/cai-tokens.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/core@3.0.0/dist/cai.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/platform@3.0.0/dist/platform.min.css">

<!-- Optional JS behaviors -->
<script type="module" src="https://cdn.jsdelivr.net/npm/@cai-ds/core@3.0.0/dist/cai.min.js"></script>

Notes

  • npm and pnpm install the required lower layers automatically; Yarn only warns, so list every package as above.
  • Pin exact versions on a CDN and add an integrity hash in production.
  • A console warning tells you when a layer is loaded without the one below it.

Package boundaries

One direction only: each package depends on the ones above it in this list.

@cai-ds/tokens   -> primitives + semantic token contracts (standalone)
      ↓ required by
@cai-ds/core     -> reusable CSS components + optional JS behaviors
      ↓ required by
@cai-ds/platform -> page and app-shell patterns

Platform can use core and tokens; core can use tokens; nothing in tokens or core may use platform. The packages declare this as required peer dependencies, and a console warning tells you when a layer is loaded without the one below it.

Button

components/button.css
Link as button

When to use

To start an action on the current page: save, send, open a dialog. Use the primary variant once per view.

When not to use

To go to another page. Use a link, or a link styled with the button class. Do not use a disabled button to hide an action.

How it works

A native button element with a variant and a size modifier. Without JavaScript it works as any button; inside a form, set the type.

Content guidance

Start with a verb and say the result: "Save changes", "Delete draft". Never "OK", "Submit" or "Click here". Sentence case.

Keyboard and ARIA

Tab to reach it, Enter or Space to press it. The focus ring is the shared 2px ring. No ARIA is needed; add an aria-label only to an icon-only button.

Known issues

None known.

Copy button

components/copy-btn.css JS: clipboard.js
var(--cai-brand-primary)

The button copies the text in its data-copy attribute.

When to use

To copy a short string the reader will paste elsewhere, such as a command or a token name.

When not to use

For long text, or where selecting the text is enough. Never as the only way to get the content.

How it works

A button with data-copy. It needs JavaScript and the Clipboard API, so it is hidden until the script runs; the text it copies is always on the page, selectable.

Content guidance

Name what is copied in the accessible name: "Copy the install command". The visible label is "Copy"; the result is announced in a polite live region.

Keyboard and ARIA

Tab, then Enter or Space. A polite status message announces "Copied to clipboard" or the failure.

Known issues

Needs a secure context (https or localhost) for the Clipboard API; the failure is announced and the text can still be selected.

When to use

To collect input. Use the native control that fits the data: text, email, date, range, select, checkbox, radio, switch.

When not to use

Do not rebuild a native control from divs. Do not use a placeholder as the label.

How it works

Native inputs with the field, label, helper and error classes. The switch is a checkbox with role="switch"; all of it works without JavaScript and submits with the form.

Content guidance

Every control has a visible label. Hints go in a helper linked with aria-describedby. An error says what is wrong and how to fix it, next to the field, prefixed with "Error:".

Keyboard and ARIA

Tab between fields, Space toggles checkboxes and switches, arrow keys move inside radio groups and sliders. Group related controls with fieldset and legend.

Known issues

Tooltip

components/tooltip.css
Tooltip content

When to use

To explain a control whose label is not enough, in a sentence at most.

When not to use

For anything essential, long or interactive. On touch devices there is no hover: put important text on the page.

How it works

CSS only: it opens on hover and on keyboard focus, and stays open while the pointer is over it (WCAG 1.4.13, hoverable).

Content guidance

One short sentence, no links. The control keeps its own accessible name.

Keyboard and ARIA

Opens when the control receives focus, closes when it loses focus. The Escape key does not close it.

Known issues

Partial WCAG 1.4.13: the tooltip cannot be dismissed with Escape without moving focus or the pointer. Keep tooltips non-essential.

Inline code looks like var(--cai-text-primary) inside a sentence.

Syntax colours in the three modes

CAI's own scheme: keywords stay ink and bold, colour goes to what the author wrote (names, properties, values), comments step back in italic. No red, because red means error. Each colour keeps 4.5:1 or more on the block, 7:1 or more in high contrast.

When to use

To show code or terminal output the reader may copy.

When not to use

For long files; link to the source instead.

How it works

A pre with a code element. Highlighting is an enhancement: without JavaScript the block is plain, readable text. With it, highlight.js wraps HTML, CSS, JavaScript (js, jsx), JSON and shell (bash, sh, shell) in six .tok-* classes, one per --cai-code-* token. In forced colors every colour becomes the system text colour; bold keywords and italic comments remain.

Content guidance

Label the language with data-lang (html, css, js, json, bash; anything else, such as text, stays plain) and name the block with aria-label.

Keyboard and ARIA

The block is focusable (tabindex 0) so it can be scrolled with the keyboard.

Known issues

Syntax colours are decoration; the code is not read differently by assistive technology. The highlighter is a set of patterns, not a parser: JSX tags, the contents of HTML style and script elements and unquoted attribute values stay plain.

When to use

To let readers browse and copy a set of icons.

When not to use

Do not use icons as the only label of an action.

How it works

A list of icons. Each item shows the icon, its name and a native copy button with the SVG in data-copy. Without JavaScript the copy buttons are hidden and the list still shows every icon and name. CAI ships the grid, not an icon set.

Each item shows the icon name in text. Decorative icons are aria-hidden.

Keyboard and ARIA

Toast

components/toast.css
SUCCESS
File exported successfully.

A static specimen: CAI styles the toast and leaves placement and timing to you.

When to use

To confirm a low-stakes result that needs no reply, such as "Draft saved".

When not to use

For errors the reader must act on, or anything they might miss: toasts disappear.

How it works

A styled block with a close button. CAI leaves placement and timing to you; if it fades, give it at least 5 seconds and let it be paused.

Content guidance

Past tense, one short line. No actions inside it.

Keyboard and ARIA

The close button is reachable with Tab. Announce the toast in a polite live region.

Known issues

CAI ships the look only: the live region and the timer are the consumer's job.

Modal

components/modal.css JS: modal.js

Confirm action

This action cannot be undone. Continue?

A native <dialog>: Esc closes it and focus returns to the button.

When to use

To ask for a decision or short input that must be settled before the reader continues.

When not to use

For information the reader can ignore: use an alert. Do not open one on page load.

How it works

A native dialog opened with showModal(). Buttons use command="show-modal" and command="close" with commandfor; a small script supplies those in browsers without them.

Content guidance

The title names the decision: "Delete this draft". Buttons repeat the action: "Delete draft" and "Cancel", never "OK".

Keyboard and ARIA

The browser traps focus, Escape closes it and focus returns to the opener. Give the dialog aria-labelledby.

Known issues

command and commandfor are not yet in every supported browser: without them and without JavaScript the open button does nothing.

Color mode switcher

components/mode-switcher.css

A native radio group for the color mode. This specimen is disabled. The working one, in the cycle variant, is in this page's footer: one button with the icon of the current mode.

Cycle variant

Add cai-mode-switcher--cycle, an icon to each label and a cai-mode-cycle button with one icon per mode (data-mode-icon). With scripting on, the button shows the icon of the checked mode and the radios hide, with no flash while the script loads; without scripting the three radios show and the button hides. initThemeCycle() from @cai-ds/core/theme (run by cai.js) makes the button step through the modes, and adds the button if the markup has none.

<fieldset class="cai-mode-switcher cai-mode-switcher--cycle">
  <legend class="cai-mode-switcher__label">Color mode</legend>
  <button class="cai-mode-cycle" type="button" aria-label="Change color mode">
    <svg class="cai-mode-btn__icon" data-mode-icon="light" viewBox="0 0 24 24" aria-hidden="true">…</svg>
    <!-- the same for data-mode-icon="dark" and "high-contrast" -->
  </button>
  <span class="cai-mode-cycle__status" role="status"></span>
  <label class="cai-mode-btn" data-theme="light">
    <input class="cai-mode-btn__input" type="radio" name="cai-theme" value="light" checked>
    <svg class="cai-mode-btn__icon" viewBox="0 0 24 24" aria-hidden="true" focusable="false">…</svg>
    Light
  </label>
  <!-- the same for dark and high-contrast -->
</fieldset>

<script type="module">
  import { initThemeCycle } from "@cai-ds/core/theme";
  initThemeCycle();
</script>

When to use

For the main navigation of a documentation or app shell with many sections. Use the cycle variant of the color mode switcher where space is short, such as a page footer or header.

When not to use

For a short list of pages: a header navigation is simpler. Do not use the cycle variant where people compare the modes side by side: the radio group shows them all at once.

How it works

A nav landmark. On small screens it is a native popover drawer opened by a button with popovertarget, .cai-nav-toggle. Put that button first in your header row, so the focus order follows the screen; .cai-nav-toggle--fixed pins it to the top start corner instead, for a page with no header. The color-mode switcher is a native radio group; checking a radio sets the mode, even without JavaScript. In the cycle variant, initThemeCycle() hides the radios and adds one button: each press checks the next mode and fires its change event, so the script that sets the mode applies it. The radios stay the source of truth.

Content guidance

Section labels are nouns. The switcher is called "Color mode", and each mode keeps its visible name next to its icon, so the radios read without the icons.

Keyboard and ARIA

Escape and a click outside close the drawer; focus returns to the button. Arrow keys move between the mode radios. The cycle button is a native button: Tab reaches it, Enter or Space changes the mode. Its name says what it does and the current mode, "Change color mode. Current: Dark", and a polite status announces the new mode.

Known issues

Without the popover API the navigation stays visible above the content. A stored color mode can flash once on load, because no inline script sets it.

MIDI, parsed and played with Web Audio by midi.js, which loads only when a MIDI player is on the page.

When to use

To play video, audio or a MIDI file in the page.

When not to use

Do not autoplay. Do not use it for background media.

How it works

Without JavaScript the native controls of the audio and video element are shown. The script replaces them with the CAI controls; seek and volume are native range inputs. MIDI needs JavaScript and Web Audio.

Content guidance

Name each player with aria-label and give video a text alternative or a transcript.

Keyboard and ARIA

Space or K plays and pauses, M mutes, F goes full screen on video. The sliders take arrow keys, Home, End and Page Up and Down.

Known issues

Captions and audio description depend on the media you provide. MIDI has no equivalent without JavaScript.

Accessibility statement

What CAI aims for, what is checked on every change, and what has not been tested. Last reviewed on 8 October 2026.

Target

CAI aims to meet WCAG 2.2 level AA, the level that EN 301 549 and the European Accessibility Act refer to. A design system cannot make a service accessible by itself: how you use the components decides the result.

What is checked on every change

  • An automated scan with axe-core of the home page and this documentation page, in the light, dark and high-contrast modes. A serious or critical finding fails the build.
  • Keyboard use of the sidebar drawer, the modal dialog and the tabs.
  • The pages with JavaScript turned off: content is readable at 320 pixels wide, and no control that needs JavaScript is left on screen doing nothing. The color mode switcher in the page header shows as three radio buttons, which still set the mode.
  • Reduced motion: no transition or animation runs when the visitor asks for less motion.
  • Forced colors: a focused button keeps a visible outline.
  • Contrast of the text written for the home and documentation pages, in all three modes.
  • Contrast of every token pair a component draws, by a script, in the three base modes and in each mode of the shipped custom themes (minimalist and vejer).

What has not been tested

  • Screen readers. No assistive technology has been used to test this release: NVDA, JAWS, VoiceOver, TalkBack and Orca have not been tried. Nothing here says a component works with them.
  • Speech recognition and screen magnifier software.
  • Zoom to 400 percent by hand. Only the 320 pixel width is measured.
  • Research with disabled people.

Automated tools find only part of the problems. Treat this list as the gap, and test your own pages.

Known issues

  • The tooltip cannot be dismissed with the Escape key. This partly fails WCAG 1.4.13 (Content on hover or focus). Keep tooltips non-essential.
  • The modal buttons use the command and commandfor attributes. In a browser without them, and without JavaScript, the open button does nothing.
  • The MIDI player needs JavaScript and Web Audio. Without them it shows a message.
  • On the home and documentation pages, a stored color mode can flash once on load, because no inline script sets it before the first paint.
  • The button of the example form on the home page opens a popover that says nothing was sent; a status region repeats it for screen readers when JavaScript runs. This has not been tested with a screen reader.

Report a problem

If something does not work for you, open an issue on GitHub and say what you were trying to do, the browser and the assistive technology you use.
