        Landing page templates

        The blocks of an event landing page to paste in and adapt, in the order a visitor reads them: hero, programme, speakers, tickets, call to action, registration and features.

        On this page
        • Hero with an image
        • Programme
        • Speakers
        • Ticket plans
        • Call to action
        • Registration form
        • Feature grid block
        • What is not here

        Each block is complete markup for the <main> of a page: start from the landing page shell, then add the blocks one after another, in the order a visitor reads them. Change the words and the links; keep one <h1>, in the hero, and an <h2> for each block.

        They use the classes of core, site and landing. Where CAI has nothing for a part, the last section says so.

        Hero with an image

        The first block of an event page: what it is, when and where, the main action and a picture. It is the hero with its image. The text comes first in the source, so it comes first for a screen reader and when the columns stack.

        • The hero gives two equal columns when each gets 24rem (the hero is 51rem wide or more: from about 900 px of window on a full-width page) and one column below. The picture is the image frame: it keeps its ratio, crops the picture to it and draws a placeholder until you have one.
        • Give the image its real width and height and an alt that says what it shows, or alt="" if it only decorates. Do not set loading="lazy" on it: it is the first thing on the page.
        • One primary button. The second action is an outline button.
        HTML 
        <section class="cai-site-hero" aria-labelledby="event-title">
  <div class="cai-site-hero__copy">
    <p class="cai-site-hero__eyebrow">12 and 13 May 2027 · Seville</p>
    <h1 class="cai-site-hero__title" id="event-title">Acme Summit 2027</h1>
    <p class="cai-site-hero__lead">Two days of talks and workshops for retail teams.</p>
    <div class="cai-site-actions">
      <a class="cai-btn cai-btn--primary" href="#register">Register</a>
      <a class="cai-btn cai-btn--outline" href="#programme">See the programme</a>
    </div>
  </div>
  <div class="cai-site-hero__media">
    <div class="cai-site-image cai-site-image--4x3">
      <picture>
        <source type="image/avif" srcset="/img/venue-640.avif 640w, /img/venue-1280.avif 1280w" sizes="(min-width: 1024px) 50vw, 100vw">
        <source type="image/webp" srcset="/img/venue-640.webp 640w, /img/venue-1280.webp 1280w" sizes="(min-width: 1024px) 50vw, 100vw">
        <img src="/img/venue-1280.jpg" width="1280" height="960" alt="The main hall, full, before the opening talk" fetchpriority="high" decoding="async">
      </picture>
    </div>
  </div>
</section>

        Programme

        A schedule is a table: the reader compares times and rooms. Below 480 px of its own width each row becomes a card of label and value pairs, so it needs no sideways scrolling on a phone.

        • One table for each day, with the day in the <caption> and in the wrapper's aria-label. For several days, repeat the table under an <h3> for each day.
        • data-label on every <td> is the name shown before the value in the stacked layout. See Table.
        HTML 
        <section class="cai-site-section" id="programme" aria-labelledby="programme-title">
  <h2 id="programme-title">Programme</h2>
  <div class="cai-table-wrap" role="region" aria-label="Programme, Wednesday 12 May" tabindex="0">
    <table class="cai-table">
      <caption>Wednesday 12 May</caption>
      <thead>
        <tr><th scope="col">Time</th><th scope="col">Session</th><th scope="col">Room</th></tr>
      </thead>
      <tbody>
        <tr><td data-label="Time"><time datetime="09:30">09:30</time></td><td data-label="Session">Opening talk</td><td data-label="Room">Main hall</td></tr>
        <tr><td data-label="Time"><time datetime="11:00">11:00</time></td><td data-label="Session">Workshop: stock in real time</td><td data-label="Room">Room 2</td></tr>
        <tr><td data-label="Time"><time datetime="14:30">14:30</time></td><td data-label="Session">Panel: the shop in 2030</td><td data-label="Room">Main hall</td></tr>
      </tbody>
    </table>
  </div>
</section>

        Speakers

        A list of people: a photo, the name and what they do. Each speaker is a card with an image frame of ratio 1:1, in a list that fits as many columns as there is room for.

        • The photo has alt="": the name is in the heading beside it and says the same. If a photo shows something the name does not carry, give it an alt that says that, never the name again.
        • The name is an <h3>, one level under the section's <h2>, so people can move through the speakers by headings. The role is the card's body: "Role, Organisation", one line.
        • The <ul> tells a screen reader how many people there are. Core styles no list: take off the bullets and the indent with the one rule of your own in the snippet. Safari can drop the list role from a list whose markers you remove; the headings still lead through the speakers.
        • .o-grid--auto puts as many columns as fit, none narrower than 16rem. Set --cai-grid-min on the list for narrower cards: 12rem gives five across a 1100 px container, and one column below 336 px stays one column.
        • No photo yet: leave the frame empty (<div class="cai-site-image cai-site-image--1x1 u-mb-sm"></div>) and it draws the placeholder. To link a speaker to a page of their own, put a link in the heading, <h3 class="cai-card__title"><a href="/speakers/luis-ortega/">Luis Ortega</a></h3>: the whole card becomes the link. Link all the speakers or none, and do not add a second link or a button.
        HTML 
        <style>
  /* Your own rule: core styles no list */
  .speakers { list-style: none; margin: 0; padding: 0; }
</style>

<section class="cai-site-section" id="speakers" aria-labelledby="speakers-title">
  <h2 id="speakers-title">Speakers</h2>
  <ul class="o-grid o-grid--auto speakers">
    <li class="cai-card">
      <div class="cai-site-image cai-site-image--1x1 u-mb-sm">
        <picture>
          <source type="image/avif" srcset="/img/marta-320.avif 320w, /img/marta-640.avif 640w" sizes="(min-width: 769px) 25vw, 100vw">
          <source type="image/webp" srcset="/img/marta-320.webp 320w, /img/marta-640.webp 640w" sizes="(min-width: 769px) 25vw, 100vw">

        </picture>
      </div>
      <h3 class="cai-card__title">Marta Ríos</h3>
      <p class="cai-card__body">Head of logistics, Grupo Lumen</p>
    </li>
    <li class="cai-card">
      <div class="cai-site-image cai-site-image--1x1 u-mb-sm">

          <source type="image/avif" srcset="/img/luis-320.avif 320w, /img/luis-640.avif 640w" sizes="(min-width: 769px) 25vw, 100vw">

        Ticket plans

        Three plans side by side above 768 px, one under another below it. Each plan is a card with its name, its price, what is included and one action.

        • .o-grid--3 gives three equal columns above 768 px. For two or four plans use .o-grid--2 or .o-grid--4, or .o-grid--auto to let the width decide.
        • .cai-card__price sets the price in semibold figures of equal width; a previous price is an <s> with a .u-sr-only "Was" before it, so the line through it is not the only cue.
        • The button says which plan it chooses ("Choose Two days"), so a list of buttons makes sense out of context. The recommended plan is a featured card with the primary button and a tag that says why, in its text; the others are outline buttons.
        HTML 
        <section class="cai-site-section" id="tickets" aria-labelledby="tickets-title">
  <h2 id="tickets-title">Tickets</h2>
  <div class="o-grid o-grid--3">
    <article class="cai-card">
      <h3 class="cai-card__title">One day</h3>
      <p class="cai-card__price"><data value="99">99 €</data></p>
      <p class="cai-card__body">Talks and lunch, on the day you choose.</p>
      <a class="cai-btn cai-btn--outline" href="/register/?ticket=day">Choose One day</a>
    </article>
    <article class="cai-card cai-card--featured">
      <h3 class="cai-card__title">Two days</h3>
      <p class="cai-card__price"><data value="149">149 €</data> <s><span class="u-sr-only">Was </span>180 €</s></p>
      <p class="cai-card__body">Both days, lunch and the recordings. <span class="cai-tag cai-tag--blue">Most chosen</span></p>
      <a class="cai-btn cai-btn--primary" href="/register/?ticket=two-days">Choose Two days</a>
    </article>
    <article class="cai-card">
      <h3 class="cai-card__title">Team of five</h3>
      <p class="cai-card__price"><data value="599">599 €</data></p>
      <p class="cai-card__body">Five tickets for both days, one invoice.</p>
      <a class="cai-btn cai-btn--outline" href="/register/?ticket=team">Choose Team of five</a>
    </article>
  </div>
</section>

        Call to action

        A reason to act now and one action, repeated near the end of a long page. It is a section on a band: the tint runs from edge to edge of the page, and the heading, one sentence and the action group keep the page's column.

        • One primary button, and it points at the form or the page where the visitor acts (#register). The heading says why now, not "Register".
        • Use a heading level that follows the page: <h2> here, because it sits beside the other sections.
        • One band for each screen height at most, and not inside a card. In forced colors the tint is removed and two thin rules mark the band.
        HTML 
        <section class="cai-site-section cai-site-section--band" aria-labelledby="last-seats-title">
  <h2 id="last-seats-title">Registration closes on 30 April</h2>
  <p>The hall holds 400 people, and the Two days ticket sold out last year.</p>
  <div class="cai-site-actions">
    <a class="cai-btn cai-btn--primary" href="#register">Register now</a>
  </div>
</section>

        Registration form

        The words on the left, the form on the right above 768 px; one column below. It is a native <form> that works without JavaScript, with the constraint validation of the browser.

        • Every field has a visible label. Say once, above the form, what "*" means. The hint is linked with aria-describedby.
        • An error says what went wrong and how to fix it; the markup is on Form fields.
        • The consent is a checkbox with a label and a link to the notice, not a sentence under the button. The button says what happens: "Complete registration", not "Submit".
        • action and the field names are yours: the form is sent to your server.
        HTML 
        <section class="cai-site-section" id="register" aria-labelledby="register-title">
  <div class="o-grid o-grid--2">
    <div class="o-stack">
      <h2 id="register-title">Register</h2>
      <p>Tell us who is coming. We email the ticket within one working day.</p>
      <p>Fields marked * are required.</p>
    </div>
    <form class="o-stack" action="/register/" method="post">
      <div class="cai-field">
        <label class="cai-field__label cai-field__label--required" for="reg-name">Full name</label>
        <input class="cai-input" id="reg-name" name="name" type="text" autocomplete="name" required>
      </div>
      <div class="cai-field">
        <label class="cai-field__label cai-field__label--required" for="reg-email">Email</label>
        <input class="cai-input" id="reg-email" name="email" type="email" autocomplete="email" required aria-describedby="reg-email-hint">
        <div class="cai-field__helper" id="reg-email-hint">We send your ticket to this address.</div>
      </div>
      <div class="cai-field">
        <label class="cai-field__label cai-field__label--required" for="reg-ticket">Ticket</label>
        <select class="cai-select" id="reg-ticket" name="ticket" required>
          <option value="">Choose a ticket</option>
          <option value="day">One day, 99 €</option>
          <option value="two-days">Two days, 149 €</option>
          <option value="team">Team of five, 599 €</option>
        </select>
      </div>
      <div class="cai-check-item">
        <input type="checkbox" id="reg-privacy" name="privacy" required>
        <label for="reg-privacy">I have read the <a href="/privacy/">privacy notice</a></label>
      </div>
      <div class="cai-site-actions">
        <button class="cai-btn cai-btn--primary" type="submit">Complete registration</button>
      </div>
    </form>
  </div>
</section>

        What is not here

        An event page often asks for things CAI does not have. They are not faked in the templates above.

        • A countdown or a map. CAI draws neither. For icons, CAI has its own set to copy.
