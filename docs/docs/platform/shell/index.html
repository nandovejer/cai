        Page shell

        .cai-platform-page --gradient .cai-platform-main .cai-platform-content

        Lays out a whole page: header, a main area that grows, and a footer that stays at the bottom.

        Known issues

        None known.

        Code Design

        Code

        Copy the markup

        HTML 
        <body class="cai-platform-page">
  <a class="cai-platform-skip-link" href="#main-content">Skip to main content</a>
  <header>…</header>
  <main class="cai-platform-main o-container" id="main-content">
    <div class="cai-platform-page-header">
      <h1 class="cai-platform-page-header__title">Billing</h1>
    </div>
    <section class="cai-platform-section" aria-labelledby="invoices-title">
      <h2 id="invoices-title">Invoices</h2>
    </section>
  </main>
  <footer class="cai-platform-footer o-container">…</footer>
</body>

        Variants and options

        ClassEffect
        .cai-platform-page
        On <body>: three rows (header, main, footer), at least the height of the screen
        .cai-platform-page--gradient
        A soft brand tint in the top corner fading into the page surface, for short pages
        .cai-platform-main
        On <main> of a page without a sidebar: stacks sections with a 64 px gap
        .cai-platform-content
        On the column next to a sidebar: padding and the maximum content width

        How it works

        CSS grid from @cai-ds/platform. No JavaScript.

        • The middle row takes the free space, so the footer stays at the bottom of short pages.
        • Use the layout objects of core, such as .o-container, for the width.
        • .cai-platform-content reduces its padding at 768 px and again at 480 px.

        Without JavaScript

        Nothing changes: the shell is CSS.

        Keyboard and ARIA

        The shell has no interaction of its own.

        • Landmarks come from the native elements: <header>, <nav>, <main>, <footer>. Do not add role to them.
        • Put a skip link first in <body>.

        Contrast and focus are in the Design tab.

        Design

        When to use

        Use the page shell for the whole page of an app or a product site: a header, a main area that grows, and a footer at the bottom.

        When not to use

        Do not use it inside a component or a card: it sets a full-height grid on its element.

        • Do not nest one page shell in another.
        • Do not use the gradient behind long text: a flat surface is easier to read.

        Do and don't

        Writing the content

        One <main> per page, with the id the skip link points to.

        • Start <main> with the page header, so the first heading is the <h1>.

        Tokens it uses

        The 9 tokens that the .cai-platform-page rules of platform's components/_components.css reads, by family. Each family links to its page, with the values in every mode. In Figma they are variables with the same names: see Tokens in Figma.

        Color
        --cai-brand-subtle, --cai-surface-muted, --cai-surface-page
        Spacing and sizing
        --cai-space-2xl, --cai-space-3xl, --cai-space-lg, --cai-space-md, --cai-space-xl
        Layers and breakpoints
        --cai-content-max
