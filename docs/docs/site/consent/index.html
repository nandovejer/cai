        Cookie consent

        .cai-site-consent __title __choices JS: consent.js

        Asks a visitor once whether the site may use optional cookies, with Accept and Reject side by side, and remembers the answer.

        Example

        Cookies on Bodega Albar

        We use cookies that this site needs to work. We would also like to measure how you use it, to improve it. Read the cookie policy.

        Choose which cookies to allow
        Optional cookies

        Your choice is saved. You can change it at any time on the cookie policy page.

        The answer of this example is stored under its own key, cai-consent-demo, so it does not count as an answer for this site. Without JavaScript the banner and its button stay hidden.

        Known issues

        Without JavaScript the banner is not shown at all: there is nothing to answer, because none of the site’s own scripts run either. A server that sets optional cookies itself, without a script, must ask some other way. The answer is kept in the browser’s local storage, so a server cannot read it, and clearing site data asks again. In a browser without CSS anchor positioning (before Chrome and Edge 125, Safari 26, Firefox 147), the site header’s menu at 768 px and below opens at the top of the window, so while the banner is shown and before the page scrolls it covers part of the header; Escape or a click outside closes it. It has not been tested with a screen reader.

        Code Design

        Code

        Copy the markup

        Right after the skip link, before a notice and the site header. One checkbox per category of optional cookies, its value the category’s name. Load the module on its own: site.js does not include it.

        HTML 
        <script type="module" src="https://cdn.jsdelivr.net/npm/@cai-ds/site@3.0.0/dist/consent.min.js"></script>

<a class="cai-site-skip-link" href="#main">Skip to main content</a>
<cai-site-consent>
  <section class="cai-site-consent" data-cai-consent aria-labelledby="consent-title" hidden>
    <div data-cai-consent-ask>
      <h2 class="cai-site-consent__title" id="consent-title">Cookies on Bodega Albar</h2>
      <p>We use cookies that this site needs to work. We would also like to measure how you
        use it, to improve it. <a href="/cookies/">Read the cookie policy</a>.</p>
      <form class="cai-site-actions">
        <button class="cai-btn cai-btn--primary" type="submit" value="all">Accept optional cookies</button>
        <button class="cai-btn cai-btn--primary" type="submit" value="none">Reject optional cookies</button>
      </form>
      <details class="cai-site-consent__choices">
        <summary>Choose which cookies to allow</summary>
        <form class="o-stack">
          <fieldset class="cai-fieldset">
            <legend>Optional cookies</legend>
            <div class="cai-check-group">
              <label class="cai-check-item"><input type="checkbox" value="analytics"> Measuring visits</label>
              <label class="cai-check-item"><input type="checkbox" value="marketing"> Adverts on other sites</label>
            </div>
          </fieldset>
          <div class="cai-site-actions">
            <button class="cai-btn cai-btn--secondary" type="submit">Save my choices</button>
          </div>
        </form>
      </details>
    </div>
    <p data-cai-consent-done tabindex="-1" hidden>Your choice is saved. You can change it at any
      time on the <a href="/cookies/">cookie policy</a> page.</p>
  </section>
</cai-site-consent>
<header class="cai-site-header">…</header>

<!-- On the cookie policy page -->
<button class="cai-btn cai-btn--outline" type="button" data-cai-consent-open hidden>Change cookie settings</button>

        Your scripts read the answer and listen for a new one. Load an optional script only for a category the visitor granted:

        JS 
        import { getConsent } from "@cai-ds/site/consent";

const granted = (answer) => answer?.granted.includes("analytics");

if (granted(getConsent())) startMeasuring();
document.addEventListener("cai:consent", (event) => {
  if (granted(event.detail)) startMeasuring();
  // Withdrawn: the simplest correct answer is to reload the page
  else location.reload();
});

        Variants and options

        There are no variants. The hooks are data-cai-consent-* attributes.

        Class or attributeEffect
        .cai-site-consent
        The banner: a band as wide as its container, its text in the site header’s column, in the sans. Keep hidden on it: the script shows it
        .cai-site-consent__title
        Its heading, in the sans; it names the banner’s region through aria-labelledby
        .cai-site-consent__choices
        The <details> with the categories, under the two buttons
        <cai-site-consent>
        The custom element the module defines. It wires the banner inside it when it connects
        data-cai-consent
        On the <section>: the banner. Optional data-cai-consent-days, how long an answer lasts (180 days by default, 395 at most), and data-cai-consent-key, the storage key (it must start with cai-)
        data-cai-consent-ask, data-cai-consent-done
        The question, and the confirmation that takes its place. The confirmation has tabindex="-1": it takes focus
        value="all", value="none"
        On the submit buttons: Accept grants every category, Reject none. A submit button with another value, or none, grants the ticked ones of its form
        data-cai-consent-open
        On a button anywhere, with hidden: the script shows it, and it shows the banner again, with the stored answer ticked

        How it works

        CSS from @cai-ds/site, two native forms and a module of its own, @cai-ds/site/consent (dist/consent.min.js, under 1 kB compressed). site.js does not import it, so only the pages that ask load it.

        • When it asks: when no answer is stored, when the stored one has expired, or when the banner offers a category the stored answer was not asked about. Then it shows, in the flow above the header: it covers nothing, traps nothing and takes no focus, so the page can be read and used before answering.
        • The answer: Accept grants every category, Reject none, Save my choices the ones ticked. Enter in a checkbox saves the ticked ones, never all. Escape is not an answer: nothing happens. The confirmation then takes the place of the question and takes focus, and is read.
        • Where it is kept: in the browser’s localStorage, under cai-consent, as JSON: {"version":1,"expires":…,"asked":["analytics","marketing"],"granted":["analytics"]}, with expires in milliseconds since 1970. Not in a cookie: a cookie would travel to the server with every request, and asking about cookies should not need one. No personal data, and nothing leaves the browser. A malformed value counts as no answer. If storage is blocked, the answer holds for the page and the next page asks again.
        • Your scripts: getConsent() returns the stored answer, { asked, granted, expires }, or null. Each new answer dispatches cai:consent on document, with the same object as detail. Category names are a lowercase letter, then lowercase letters, digits or hyphens, 32 at most.
        • Changing the answer: as easy as giving it. A button with data-cai-consent-open, on the cookie policy page, shows the banner again. Put one banner on a page: every such button opens it.
        • The script writes no text: every word is in your markup, in the page’s language.

        Without JavaScript

        The banner and the button that shows it again stay hidden, by their hidden attribute. Without a script none of the site’s own scripts run, so there is nothing to ask about, and buttons that would do nothing are never shown. Link the cookie policy from the footer of every page, so it can always be read.

        Keyboard and ARIA

        • Order: the skip link stays first, so a returning visitor can still jump to the content. The banner comes next, before the header: the policy link, Accept, Reject, then the button that opens the categories.
        • Keys: Enter or Space on a button; Space ticks a checkbox. Escape does nothing.
        • Landmark: a <section> named by its heading is a region, listed among the landmarks, before the banner landmark of the header. It is not a dialog: it does not block the page, so it needs no role="dialog".
        • Focus: none when the page loads. After an answer, the confirmation; after the button that shows it again, the banner.

        Contrast and focus are in the Design tab.

        Design

        When to use

        Use it when your site sets cookies, or stores data in the browser, that it does not need to work, such as measuring visits or adverts: the law in the EU and the UK asks for the visitor’s consent before that.

        When not to use

        Do not use it when the site sets only the cookies it needs to work (a session, a basket, a language or colour choice): those need no consent. Say so in the cookie policy and show no banner.

        • Do not use it as a wall that hides or blocks the page until the visitor answers.
        • Do not use it for news or a sale: that is a notice.

        It replaces a third-party consent script. Nothing in CAI is removed.

        Do and don't

        Writing the content

        Say in a sentence what the site needs and what it would like, and why, in plain words. Name the heading after the site: “Cookies on Bodega Albar”.

        • Write the buttons as the action and the thing: “Accept optional cookies”, “Reject optional cookies”; never “OK”, “Got it” or “Agree”.
        • Name each category after what it does for whom: “Measuring visits”, “Adverts on other sites”, not “Performance” or “Targeting”.
        • Link the cookie policy by its name, and say in the confirmation where the answer can be changed.

        Tokens it uses

        The 11 tokens that the rules of site’s components/banners.css read for the banner, by family; the buttons, the box of the categories and the checkboxes are core’s. Each family links to its page, with the values in every mode. In Figma they are variables with the same names: see Tokens in Figma.
