        Tokens in Figma

        dist/cai-tokens.dtcg.json

        The tokens as one design-tokens file for Figma variables and other design tools, with the same names and the three modes.

        On this page

        • One rule for every name
        • Figma modes and color modes
        • Import it

        !

        Not tested in Figma yet

        Nobody has imported this file into Figma or Tokens Studio yet. The limits below come from Figma's help and from reports, checked on 9 October 2026. What a test does check is that the file matches the CSS. If you import it, tell us what happened.

        Get the file

        @cai-ds/tokens includes every token in the W3C Design Tokens (DTCG) JSON format, in one file. pnpm tokens:build generates it from the same sources as the CSS, so the two always match.

        Path 
        node_modules/@cai-ds/tokens/dist/cai-tokens.dtcg.json
        • From a bundler or a script: import tokens from "@cai-ds/tokens/dtcg" (the ./dtcg export).
        • Without installing anything: https://cdn.jsdelivr.net/npm/@cai-ds/tokens@3.0.0/dist/cai-tokens.dtcg.json. Download it, then import the downloaded file.

        The file has two groups, one for each Figma collection you want:

        Group in the fileMeant as the collectionModesComes from
        primitives
        CAI primitives
        One: Value
        tokens.json: colour scales, space, control sizes, type, radius, shadows
        semantic
        CAI semantic
        Light, Dark, High contrast
        src/semantic.css: the 55 colours that change with the mode

        A semantic token points at a primitive whenever the CSS does: --cai-divider is var(--cai-gray-20) in light mode, so divider is an alias of {primitives.gray.20}. Motion, layers and breakpoints ship with @cai-ds/core, so they are not in the file.

        One rule for every name

        Remove --cai-. The first word becomes the group and the rest becomes the name, joined by a slash.

        CSS custom propertyFigma variableCollection
        --cai-surface-page
        surface/page
        CAI semantic
        --cai-text-secondary
        text/secondary
        CAI semantic
        --cai-color-danger-bg
        color/danger-bg
        CAI semantic
        --cai-space-md
        space/md
        CAI primitives
        --cai-blue-60
        blue/60
        CAI primitives

        One exception: --cai-surface is also the name of a group, so in the file it is surface/$root. Figma joins nested groups with slashes, so a tool that keeps the top group writes semantic/surface/page: the rest of the name does not change.

        Figma modes and color modes

        Each mode of the semantic collection matches one value of data-theme on <html>. So a frame set to Dark in Figma shows what the page shows with data-theme="dark".

        Figma modedata-themeWhere it is in the file
        Light
        light, or none
        $value, and $extensions.mode.Light
        Dark
        dark
        $extensions.mode.Dark
        High contrast
        high-contrast
        $extensions.mode["High contrast"]

        The two looks that ship with core, minimalist and vejer, are not in the file. To have them in Figma, add them as extra modes and copy their values from their CSS files. This step is optional.

        Import it

        Two ways in. Neither has been tried with this file yet.

        • Tokens Studio or Terrazzo: they read DTCG files, so load this one as it is. The Dark and High contrast values are in $extensions.mode, a CAI extension that is not part of the DTCG standard, so check that your tool turns them into modes.
        • Figma, without a plugin: the Variables panel imports DTCG files, but it makes one mode for each file, and an alias to another collection needs Figma's own com.figma.aliasData extension. This file therefore needs a conversion step first, described below. Imported as it is, you get the Light values only.

        To convert the file for Figma's own import, with a short script or by hand:

        1. Write the primitives group to a file of its own, and import it as the CAI primitives collection.
        2. For each mode (Light, Dark, High contrast), write a file with the semantic group, where each token's $value is its value under $extensions.mode for that mode.
        3. In those files, give each alias to a primitive ({primitives.gray.90}) the com.figma.aliasData extension that names the variable in CAI primitives, or write the colour instead of the alias.
        4. Import the Light file to create the CAI semantic collection, then each of the other two files with Import mode, named Dark and High contrast.

        Files ready for each mode may ship in the package later, once an import has been checked in a real Figma file.

        Known limits

        From Figma's help on modes and import (read on 9 October 2026) or from other users' reports, and not checked against this file:

        • Import the primitives before the semantic tokens, which point at them, if your tool makes two collections. Otherwise the aliases cannot resolve.
        • Descriptions are lost. Figma's help does not mention them, and users report that they do not arrive. Each token's job is on the Color page.
        • Sizes in rem are skipped. Figma takes dimensions in px only, and the type scale is in rem.
        • Font stacks are skipped. Figma takes a single font name, not a list. Set the fonts in Figma's text styles.
        • Modes need a paid Figma plan (Professional, Organization, Enterprise or Education), and the number of modes per collection depends on the plan.

        Keep Figma and the code in step

        • Import again whenever @cai-ds/tokens changes version. The file is regenerated with every release.
        • Never change a value in Figma alone: change the token in the code, and Figma follows on the next import.
        • Name your own variables with the same rule, so a designer and a developer use the same words.
