Type scale and minimum sizes

Every size is in rem, so text follows the font size the reader sets in the browser, not only page zoom (WCAG 1.4.4). The scale is the same at every viewport width: no breakpoint makes text smaller. Above the 16px base each step is the one before times 1.25, rounded to whole pixels; below it are the readability floors.

Font-size tokens
TokenValueAt 16px rootUse
--cai-text-xs0.75rem12pxAbsolute floor. Micro-copy only: badges, tags, counters, version labels. Never running text.
--cai-text-sm0.875rem14pxFloor for secondary and UI text: helper and error text, captions, table headers, breadcrumbs, tooltips.
--cai-text-md0.9375rem15pxDefault UI text: buttons, labels, table cells, tabs, navigation.
--cai-text-base1rem16pxBody and running text. Form fields on touch screens.
--cai-text-lg1.25rem20pxLead paragraphs, dialog titles.
--cai-text-xl1.5625rem25pxHeadings.
--cai-text-2xl1.9375rem31pxHeadings.
--cai-text-3xl2.4375rem39pxPage titles.
--cai-text-4xl3.0625rem49pxDisplay.
  • Body text is never below --cai-text-base (16px), with a line height of 1.5.
  • Secondary and UI text is never below --cai-text-sm (14px).
  • Nothing goes below --cai-text-xs (12px). Sizes relative to their context (kbd, time, output, inline code, captions) are clamped with max() so they cannot fall below the floor inside small text.
  • Form fields use --cai-text-control (core setting): --cai-text-md on desktop, --cai-text-base (16px) at 768px and below and on touch screens, where iOS Safari zooms the page into any smaller field.
