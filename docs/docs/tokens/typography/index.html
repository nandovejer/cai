        Typography

        The three font stacks, the type scale in rem, and the smallest size each kind of text may use.

        • --luz-font-sans System sans 400 600 700 italic
        • --luz-font-serif ET Book 400 600 700 italic
        • --luz-font-mono System mono 400 700 italic
        • --luz-text-xs 0.75rem · 12px Light, Usable & Zero-dependency
        • --luz-text-sm 0.875rem · 14px Light, Usable & Zero-dependency
        • --luz-text-md 0.9375rem · 15px Light, Usable & Zero-dependency
        • --luz-text-base 1rem · 16px Light, Usable & Zero-dependency
        • --luz-text-lg 1.25rem · 20px Light, Usable & Zero-dependency
        • --luz-text-xl 1.5625rem · 25px Light, Usable & Zero-dependency
        • --luz-text-2xl 1.9375rem · 31px Light, Usable & Zero-dependency
        • --luz-text-3xl 2.4375rem · 39px Light, Usable & Zero-dependency
        • --luz-text-4xl 3.0625rem · 49px Light, Usable & Zero-dependency
        • --luz-type-base1rem · 16pxThe size of --luz-text-base, and the base the other steps are computed from
        • --luz-type-ratio1.25The multiple between two steps above the base, and the divisor below it

        Two knobs size the whole scale. Set them on :root, in rem, in CSS of your own; a knob set on body or on a section changes nothing. Components read the --luz-text-* steps, never the knobs.

        Font roles

        • --luz-font-bodyvar(--luz-font-serif)Running text: the serif. Controls, labels, tables and navigation keep the sans
        • --luz-font-headingvar(--luz-font-serif)Heading font family
        • --luz-text-bodycalc(var(--luz-text-base) * 1.0625)Running text, 17px at the defaults: a step above the base, because ET Book's x-height is small. It follows the base knob
        • --luz-text-controlvar(--luz-text-md)Form field text; at least 16px (max(1rem, --luz-text-base)) at 768px and below and on touch screens

        These four ship with core, not with tokens.

        Type scale and minimum sizes

        Every size is in rem, so text follows the font size the reader sets in the browser, not only page zoom (WCAG 1.4.4). The scale is the same at every viewport width: no breakpoint makes text smaller. Above the 16px base each step is the one before times 1.25, rounded to 1/16 rem (a whole pixel at the default); below it are the readability floors.

        Font-size tokens
        TokenValueAt 16px rootUse
        --luz-text-xs0.75rem12pxAbsolute floor. Micro-copy only: badges, tags, counters, version labels. Never running text.
        --luz-text-sm0.875rem14pxFloor for secondary and UI text: helper and error text, captions, table headers, breadcrumbs, tooltips.
        --luz-text-md0.9375rem15pxDefault UI text: buttons, labels, table cells, tabs, navigation.
        --luz-text-base1rem16pxThe base of the scale, and UI text at a larger size. Form fields on touch screens. Running text is --luz-text-body, a step above it.
        --luz-text-lg1.25rem20pxLead paragraphs, dialog titles.
        --luz-text-xl1.5625rem25pxHeadings.
        --luz-text-2xl1.9375rem31pxHeadings.
        --luz-text-3xl2.4375rem39pxPage titles.
        --luz-text-4xl3.0625rem49pxDisplay.
        • Body text is --luz-text-body (17px at the defaults), with a line height of 1.6.
        • Secondary and UI text is never below --luz-text-sm (14px).
        • Nothing goes below --luz-text-xs (12px). Sizes relative to their context (kbd, time, output, inline code, captions) are clamped with max() so they cannot fall below the floor inside small text.
        • Form fields use --luz-text-control (core setting): --luz-text-md on desktop, max(1rem, var(--luz-text-base)) at 768px and below and on touch screens, never under 16px, where iOS Safari zooms the page into any smaller field.
