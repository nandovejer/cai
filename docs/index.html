Build accessible websites with plain HTML and CSS

CAI is a design system of tokens, components and page layouts. Add two <link> tags and you get forms, dialogs, tables and three color modes. No framework, no build step, and every component works without JavaScript.

Why teams use CAI

For sites and tools that should work for everyone, on any device, for years, without a framework to keep up with.

  • 01

    Works without JavaScript

    Components are native HTML elements: <dialog>, <details>, form controls, popovers. JavaScript only adds polish, so pages keep working when a script fails.

  • 02

    Accessible by default

    Keyboard support, visible focus, 4.5:1 text contrast and a high-contrast mode are part of every component. Each one comes with guidance on when to use it and when not to.

  • 03

    Nothing to install to try it

    Plain CSS and small ES modules from a CDN or npm. No preprocessor, no compiler, zero dependencies: what you read in the files is what the browser runs.

Adopt it one layer at a time

Three packages, one direction. Each layer needs the ones below it and nothing above it, so pick the level you need and stop there.

Level 1

Tokens only

Standalone

Your CSS, your components, CAI's values. One stylesheet of custom properties plus one MIT-licensed font.

  1. tokens
  2. core (not included)
  3. platform (not included)

You get

  • 52 color primitives in 7 families
  • 54 semantic tokens, each defined for light, dark and high contrast
  • Spacing (12), control heights (4), type sizes (9), radii (6) and shadows (3)
  • ET Book for headings, self-hosted and MIT licensed; system fonts for text and code

Stop here if

you already have components or a framework and only want consistent values and color modes.

See the tokens

Install

$ npm install @cai-ds/tokens
CDN 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@cai-ds/tokens@3.0.0/dist/cai-tokens.min.css">

Bringing your own fonts? Load dist/tokens.min.css instead: the same tokens with no @font-face.

Level 2

Tokens + Core

Requires tokens

Ready-made components and layout objects that consume the tokens, plus optional JavaScript for the interactive ones.

  1. tokens
  2. core
  3. platform (not included)

You get

  • 20 components: buttons, forms, tables, tabs, modal, media player and more
  • 7 layout objects and a small set of utilities
  • Motion, z-index and breakpoint settings
  • Optional cai.min.js: one ES module that wires tabs, modals, copy buttons and players

Stop here if

you are building pages or an app and bring your own page layout.

Need a single component? Load dist/base.min.css plus the file you want, for example dist/components/button.min.css.

Level 3

Tokens + Core + Platform

Requires core + tokens

The full stack: app-shell patterns for whole pages. This landing is built at this level.

  1. tokens
  2. core
  3. platform

You get

  • Page, main, content and section wrappers with a consistent vertical rhythm
  • Page header, action group, feature grid and footer
  • Skip link and command block
  • CSS only: no extra JavaScript

That is everything

There is no level 4.

Installing with Yarn or pnpm?
pnpm add and yarn add take the same package lists. npm and pnpm install the required lower layers for you; Yarn only warns, so always list every package as shown.

On a CDN, pin the exact version and add an integrity hash in production.

When CAI fits

A good fit

  • Content sites, documentation and public services that must meet WCAG 2.2 AA.
  • Server-rendered pages and static sites, in any back-end language.
  • Teams that want to read and own their CSS.

Not a good fit

  • You need ready-made React or Vue components.
  • You need a data grid, charts or a date-range picker: CAI has none.
  • You need a stable API today: CAI is in beta, and names can still change.
